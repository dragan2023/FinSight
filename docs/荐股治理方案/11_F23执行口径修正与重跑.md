## 1. 缺陷与修法

### 1.1 原实现的问题

```python
if execute and desired != position:
    if position:                      # 平仓
        cash *= (1-costs)             # ← 只扣成本，不漏掉 close_{i-1} → open_i 的隔夜变动
        ...
    if desired:                       # 开仓
        cash *= (1-costs); ...; entry=bar.open
if i and position: cash *= bar.close/bars[i-1].close   # ← 开仓当日按前收→收盘计一整段
```

后果（有跳空时）：

- **开仓当日**：按 `close_i/close_{i-1}` 计收益，却只按 `open_i` 扣成本 —— 等价于"按前收成交"，
  高开时**偏乐观**；
- **平仓当日**：把仓位按 `close_{i-1}` 计价就卖出，**漏掉 `close_{i-1} → open_i` 的隔夜变动**；
- 于是净值曲线与 `trades[].return_pct`（`open → open`）**互相矛盾**，`hit_rate` /
  `average_win_pct` / `profit_loss_ratio` 与净值是两套账。

### 1.2 修法

一律按**成交价（开盘）**盯市：

| 情形 | 净值乘子 |
|---|---|
| 平仓 | `(open_i / close_{i-1}) × (1−c)` |
| 开仓 | `(1−c) × (close_i / open_i)` |
| 持有 | `close_i / close_{i-1}` |
| 空仓不变 | 无 |

修完后的**不变式**：一笔交易期间的**净值比恰好等于该笔交易记录的收益率**。
这不只是"看起来对了"——它把曲线与 trade 日志这两本账合并成了一本。

**信号完全没变**：`desired` 只依赖 `features` 与 `bars[i-1].close`，因此交易日期、
笔数、仓位序列与修复前逐项相同（有测试 pin 住）。

### 1.3 守卫测试（`tests/unit/test_backtest_execution_consistency.py`，5 个）

1. 开仓当日按**开盘价**盯市：`(1−c)·close_i/open_i`，并断言旧口径会得到更大的值
   （证明测试能区分两套算法）；
2. **核心不变式**：交易区间的净值比 == `1 + trades[].return_pct/100`；
3. 平仓当日盯市到**开盘成交价**（构造大幅低开）；
4. **无跳空时两套算法一致**——把"缺陷为什么长期隐身"这件事本身钉住，
   免得以后有人以为"没跳空也没差"是 bug；
5. 修复**不改信号**：交易日期/笔数/仓位序列与修复前逐项相同。

## 2. 修正口径下重跑全市场扫描

### 2.1 三路对照（trend_20_60_v1，5286 只）

| 对照 | candidate | 其中跑赢基准 | 过交易门禁 |
|---|---|---|---|
| 旧：真实开盘（**有缺陷记账**） | 143 (2.71%) | 36 | 3030 |
| **新 A：真实开盘 + 修正记账** | **118 (2.23%)** | **28** | 3030 |
| 旧 B：无跳空 | 143 (2.71%) | 36 | 3030 |
| **新 B：无跳空 + 修正记账** | **143 (2.71%)** | **36** | 3030 |
| 旧 C：安慰剂 | 279 (5.28%) | 110 | 3130 |
| **新 C：安慰剂 + 修正记账** | **279 (5.28%)** | **110** | 3130 |

（新 A 的完整分布：`trend_20_60_v1` candidate 118 / experimental 2912 / insufficient 2256；
`reversal_5d_v1` insufficient 5286。结果落盘 `data/exports/sweeps/2026-09-13-{full,nogap,placebo}-f23/`。）

### 2.2 三个读法

**读法一：新 B ≡ 旧 A ≡ 旧 B，逐项相同。** 当 `open_i = close_{i-1}` 时，修正后的记账
**代数上退化为**旧记账（开仓 `(1−c)·close_i/close_{i-1}` 相同，平仓的
`open_i/close_{i-1} = 1` 因子消失）。这三组数字逐项一致（143 / 36 / 3030），
**证明修复只改了"让开盘价真的参与计算"这一件事，没有夹带别的改动**。
这是比"我测了几个用例"强得多的证据。

**读法二：旧记账系统性偏乐观。** 真实数据有跳空，于是 143 → 118、36 → 28。
即：按前收成交却只按开盘扣成本，**高开时白拿了一段涨幅**。偏差约 **21%**
（143/118 − 1）。F23 因此不是"文档没对齐"的美化问题，而是一个**会抬高结论的缺陷**。

**读法三：安慰剂对照组完全不变（279）。** 因为安慰剂序列的执行价本来就是
`open_i = close_{i-1}`（无跳空），记账修复对它是个恒等变换。这同时说明
**真实组的下降不是修复引入的噪声，而是跳空被正确计入的结果**。

### 2.3 判定不变，而且更强

| 决策 | 旧结果 | 新结果 | 是否改变 |
|---|---|---|---|
| **D17** `trend_20_60_v1` 未检出优势 | 真实 143 < 安慰剂 279；跑赢基准 36 < 110 | 真实 **118** < 安慰剂 279；跑赢基准 **28** < 110 | **不变，且差距更大** |
| **D18** `reversal_5d_v1` 退役 | 0/5286 过交易门禁 | **0/5286** | **不变** |

**结论：修好执行口径后，策略看起来更差而不是更好。** 这正是"把评价口径做实"应有的方向——
修复一个偏乐观的记账，理应让结论更难通过；如果修完变好了，反而要怀疑修错了方向。
