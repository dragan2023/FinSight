# 配股口径修正（公司行动总收益）

> 承接 `18` §6 与决策 **D49**。父任务：加速（`18`）。本文档记录那处**口径缺陷的修正**、
> 影响面量化、受影响评价的重跑对比，以及为什么它**没有**改变任何结论。

---

## 1. 一句话结论

`screener.service.total_return` 与 `_factor_value` 的动量项此前写成 `(1 + 送股)`，
**漏掉配股比例**；仓库里 P0-1 验证过的规范式子要求配股进乘数。修正后：

- 受影响单元：**10,154,444 个有前向收益的 (日期, 标的) 单元中 1,411 个（0.0139%）**；
- 重跑两处评价：IC 的 t 变动 **≤ 0.015**、事件研究三个字段的 t 变动 **≤ 0.009**；
- **没有任何结论改变**（IC 仍无因子过 \|t\|≥1.96；封单类结论仍在，且仍过族级门槛）。

**这是修 bug，不是改定义**——两处 docstring 与规范实现本来就要求配股进乘数，是**实现**没跟上。
因此没有新开因子/设计 reference，只按 G3 留变更痕迹并开新批次。

---

## 2. 错在哪（经济学与代码两层）

持有 1 股，按比例 `r`、价格 `p` 参与配股后持有 `1+r` 股，成本 `r×p`。所以窗口总收益是：

```
((1 + r) × close_h + 分红 − r × p) / close_t − 1
```

旧实现写成 `(close_h × (1 + 送股) + 分红 − 配股成本) / close_t − 1`——
**只扣了配股成本，没把配股拿到的新股算进去**，于是窗口内有配股的标的收益被系统性算低。

真实库踩到的一例（000977.SZ）：`close_t=17.63`、窗口末收盘 `16.25`、10 配 3（`rights=0.3`、
配股价 10.34 → 成本 3.102）：

| 口径 | 计算 | 结果 |
|---|---|---|
| 正确 | (16.25 × 1.3 − 3.102) / 17.63 − 1 | **+2.229%** |
| 旧实现 | (16.25 − 3.102) / 17.63 − 1 | **−25.42%** |

两者**符号相反**，所以这不是舍入级别的差别。这条例子已固化为回归测试
（`tests/unit/test_total_return_rights.py`）。

三处同源位置一并修正（**grep 出全部，不留隐蔽的不一致**）：

| 位置 | 用途 |
|---|---|
| `service.total_return` | 事件研究与横截面 IC 共用的窗口收益 |
| `service._factor_value("momentum_60d")` | 60 日动量因子 |
| 面板 SQL（`PANEL_BUILD_SQL`） | 预计算面板的 `forward_return`（版本 v3 → **v4**） |

规范实现 `repository.corporate_action_total_return_history` 本来就是对的（`(1 + 送股 + 配股)`），
这次是让另外三处向它对齐。

## 5. 一个报告口径的注意点（**已发现，未修**）

`--family-prior-statistics` 是**全局**参数，而族级多重检验计数本应**按字段各自的族**给：
- `continue_day_cnt` / `seal_money` 是封单族的第一轮（族级 = 本轮 20 条 → 门槛 3.023）；
- `seal_ratio` 属于同一族且此前已看过 20 条（族级 = 40 条 → 门槛 **3.227**）。

所以 `--field all` 那一跑里 `seal_ratio` 的门槛显示 3.023（偏低），
**封成比的规范数字是带 `--family-prior-statistics 20` 的那一跑（门槛 3.227）**，
本文档 §4.2 与 `15`/`17` 引用的也是它。每一份 JSON 里都带
`multiplicity.family_prior_statistics`，读者可自行核对。

列进待办：把族级计数改成**按字段**指定（避免同一命令里几个字段被迫共用同一个计数）。

## 6. 决策

| # | 决策 | 理由 |
|---|---|---|
| **D50** | 口径缺陷的修正**按 bug 修复处理**（登记变更 + 开新批次 + 重跑对比），**不新开因子/设计 reference** | §3：定义未变、实现没跟上；新开 reference 会让"这个因子的定义"变得难以解读 |
| **D51** | 影响面 ≤0.02% 级别的修正，**仍必须重跑并如实报告差异**，不得以"影响很小"为由跳过 | §4：跳过就等于把"结论未变"当成假设；重跑只要 75 秒（`18` 的加速让这件事变便宜） |
| **D52** | 发现一处口径实现与 docstring/规范实现不一致时，**必须 grep 出全部同源位置一并修** | 本次三处（窗口收益 / 动量因子 / 面板 SQL）；只修一处会留下更隐蔽的不一致 |
