## 1. 一次必须记下来的方法学错误

### 1.1 第一版错在哪

第一版的"安慰剂通过率"是这样算的：每个评估日把**前向收益在标的之间随机重排**，重算 Rank IC
200 次得到零分布，看真实 IC 是否超过该分布的 95 分位。首跑结果：

```
因子              方向    均值IC   IC>0占比    安慰剂通过率
momentum_60d     high   -0.0051   0.5238      0.5238
bias_20          low    -0.0012   0.4286      0.2381
volatility_20d   low     0.0401   0.6667      0.5238
```

**`momentum_60d` 的均值 IC 是 −0.005（基本为零），却有 52% 的交易日"通过"**——这不可能是真的。
真零分布下通过率应≈0.05。

### 1.2 根因（实测数字）

| 因子 | 真实 IC 的逐日 sd | 逐标的置乱零分布的 sd | 倍数 |
|---|---|---|---|
| momentum_60d | **0.1573** | 0.0232 | **6.8×** |
| bias_20 | **0.0951** | 0.0232 | **4.1×** |
| volatility_20d | **0.1321** | 0.0232 | **5.7×** |

个股收益之间有强横截面相关（共同市场因子）。**把收益在标的之间置乱，会把这层相关一起打碎**，
于是零分布只剩下 IID 的那点离散度（≈1/√n）。真实 IC 的离散度是它的 4–7 倍，
所以哪怕因子毫无信息，它也会经常"超过 95 分位"。

### 1.3 正确的检验

**均值 IC 的显著性来自 IC 时间序列的 t 值**：`t = mean(IC) / (sd(IC) / sqrt(T))`。
IC 的逐日离散度**本身就包含了**横截面相关带来的不确定性，不需要（也不应该）用一个打碎相关性的
零分布去估它。本期的抽样是按交易日等距抽取 24 个评估日（实际可用 21 个），
间隔约 100 个交易日，远大于 20 个交易日的前瞻期，因此 IC 之间近似独立，t 值可解释。

修正后的结果：

| 因子 | 方向 | 均值 IC | IC 标准差 | **t 值** | IC>0 占比 | 判定 |
|---|---|---|---|---|---|---|
| `momentum_60d` | high | −0.0051 | 0.1573 | **−0.15** | 0.5238 | 与噪声无异 |
| `bias_20` | low | −0.0012 | 0.0951 | **−0.06** | 0.4286 | 与噪声无异 |
| `volatility_20d` | low | +0.0401 | 0.1321 | **+1.39** | 0.6667 | 与噪声无异（未过 1.96） |

**安慰剂在这里保留，但角色变了**：它是**机制自检**（打碎联系后应当≈0，否则说明取数或对齐
环节有问题），**不是显著性门槛**。这一点已写进代码注释、报告字段与方法说明，
并有两条测试钉住（`test_significance_comes_from_the_ic_t_statistic_not_from_the_placebo`、
`test_ic_report_does_not_expose_a_placebo_based_pass_rate`）——防止那条错路被再走一遍。

> **顺带纠正我自己的一次误读**：看到 `volatility_20d` 均值 IC +0.040 时，我一度按
> `1/sqrt(n)` 估 SE 得出"12.9 个标准差、高度显著"。那是同一个错误——`1/sqrt(n)` 假设
> 个股独立，而它们不独立。正确的 SE 来自 IC 时间序列（0.1321/√21 = 0.0288），t 只有 1.39。

## 2. 交付物

### 2.1 固定 SQL 模板的横截面取数

`WarehouseRepository.cross_section(date_ms, history_days=400)`：一次 SQL 取回全市场在评估日 T 的
量价与流动性原料。

- **as-of 截断**：行情行与公司行动事件都以 `date_ms <= T` 为界；
- **只在 T 当日有成交**才进入结果（`last_ms = T`），停牌标的自然被排除；
- **动量用公司行动总收益口径**：把窗口 `(T−20, T]` / `(T−60, T]` 的送股/配股/现金分红
  折算进比值——P0-1 的口径下沉到 SQL 一次算完；
- 实测：5548 只 / **0.3–0.4 秒** / 重复取数逐项一致。

另有 `settlement_returns(date_ms, horizon_days)`，**仅用于结算与回溯评估**——它必然包含评估日
之后的信息，docstring 明确标注不可作为信号输入。

### 2.2 股票池规则（显式、逐条可解释）

| 规则 | 说明 |
|---|---|
| `non_positive_price` | 收盘价或前收 ≤ 0，数据异常 |
| `insufficient_history` | 回溯不足 `min_history_bars`（默认 252） |
| `below_min_turnover` | 20 日均成交额 < `min_turnover_20d`（默认 2000 万）——**不可执行，而非不看好** |
| `suspected_limit_up` | 涨幅 ≥ 9.8% 且收盘 = 最高（**涨停封板代理指标**） |
| `no_bar_on_date` | 评估日无成交（疑似停牌/退市） |

**明确写出做不到的四项**（`UNSUPPORTED_EXCLUSIONS`，常驻披露）：ST/*ST 无法识别（本地没有
`is_st` 字段）、退市证券池不存在（幸存者偏差）、真实停牌/涨跌停只能用价量代理、
不区分上市时间。

实测排除：5548 → 5125（历史不足 166、成交额过低 215、疑似涨停 41、价格异常 1）。

### 2.3 确定性排序与可回溯

- 因子按**声明方向**折算成 0–1 偏好分（`high` 越大越好 / `low` 越小越好）；
- 缺失值**不填 0**（那等于假装"最看空"），而是按可用因子归一化并记录 `factors_used`；
- 排序 **分高在前、同分按代码升序**——tie-break 是"可复现"的关键；
- 每行都带：因子原始值、偏好分、方向、`bars`、`data_as_of`、`data_source`、20 日均成交额；
- `params_hash` = `(因子集版本, 评估日, 池规则, 因子 id, 权重, top_n)` 的 sha256 前 16 位；
  规则或权重一变，哈希即变（有测试）。
- 输出一律标注 **「候选池（研究用，不是买入清单）」** + 免责声明（D7）。

### 2.4 因子声明（A.1）

| 因子 | 方向 | 先验逻辑 |
|---|---|---|
| `momentum_60d` | high | 趋势延续：中期相对强势的标的随后表现优于弱势标的 |
| `bias_20` | low | 短期均值回归：价格显著偏离 20 日均线后向均线回归 |
| `volatility_20d` | low | 低波动异象：同等收益下波动更低的标的风险调整后表现更好 |

`turnover_20d` 是**股票池过滤条件而非 alpha 因子**——把它混进打分会让"好公司"与"能买"
互相污染，也让 IC 无法解释。

## 3. 决策（D23–D27）

| # | 决策 | 理由 |
|---|---|---|
| **D23** | **因子显著性一律用 IC 时间序列 t 值**；逐标的置乱安慰剂只作机制自检，**不得**作显著性门槛 | 实测零分布离散度仅为真实 IC 的 1/4–1/7，用它当门槛会把纯噪声判成显著（首版实测通过率 0.24–0.52，真零分布下应≈0.05）。已写进代码与测试 |
| **D24** | **第一期 3 个因子全部未通过 \|t\| ≥ 1.96 → 不进入候选池打分**（只作研究基础设施保留） | 这是合格结论（方案 02 §10）。**严禁**延长观察期、增加评估日或降低门槛直到它显著——那正是被禁止的"延长观察期来修复结论" |
| **D25** | 候选池**可以产出**，但必须标注「研究用，不是买入清单」+ `params_hash` + 全部限制说明；**不得**当作荐股产出 | 它是 C3 评价口径的基础设施，不是结论。D7 要求候选池不得称"买入清单" |
| **D26** | 若要在大样本上确认 `volatility_20d`（t=1.39，唯一偏正），**必须作为新假设重新预注册并开新批次** | 首次评价在登记之前就跑了，其 t 值属**探索性**而非确认性；在同一批次里加日期直到显著＝事后调参 |
| **D27** | `volatility_20d` 与 `momentum_60d` 高度相关，**合并打分时必须显式去重或声明** | 等权合成会把同一件事算两遍。本期未合并（因为都没过门槛），但这条约束对下一期有效 |
