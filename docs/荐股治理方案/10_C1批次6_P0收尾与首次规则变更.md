## 1. P0-5：文档口径（D15）

### 1.1 `scripts/doc_lint.py` 的三项检查

| 检查 | 判据 | 为什么值得机器化 |
|---|---|---|
| **路径** | 文档里反引号包起来的仓库路径必须真实存在（允许唯一后缀简写，如 `advisor/graph.py`） | F10 的教训：11 条路径里 9 条不存在，人工核对过一次之后**又腐化了** |
| **版本号** | 策略方法卡声明的版本必须与 `strategy/registry.py` 一致 | 方法卡写 v1 而代码是 v2，`service.py` 会因此抛 `strategy_version_mismatch` |
| **常量** | 说明书里写的顾问超时值必须与 `advisor/graph.py` 的常量一致 | 文档写 25/75 秒，代码是 120/360 秒 |

**两个设计细节**（都是首跑暴露出来的）：

1. **白名单不能放待修项**。第一版把 F10 列出的失准路径放进了白名单，结果它们被"吞掉"、
   不再报告——那正是 P0-5 要修的东西。现在白名单只放**文档在讲"它已不存在"**的路径。
2. **通配符不是缺失**。`backend/app/api/*.py` 这类写法只要求父目录下至少有一个匹配文件，
   否则会变成误报。

## 2. P0-4.1 / 4.2：数据溯源口径（D9 / D10）

### 2.1 实测事实（与交接件的差异要记录）

| 项 | 交接件说法 | 实查结果 |
|---|---|---|
| `market_datasets` / `market_sync_runs` 位置 | 未说明 | **在 SQLite**（`data/db/finsight.db`），**不在 DuckDB** |
| `financial_statements` 的 `evidence_id` | "全为空串" | 确认：**1,316,176 行全部为空串** |
| `.git` 体积 | "重写历史后大量对象不可达，执行 gc 可显著缩小" | 实测 **3.17 MiB**、`in-pack 885`、**`garbage: 0`** → **gc 已无需执行** |

### 2.2 落地

**代码侧**（`backend/app/market_warehouse/schema.py`）新增两个常量：

- `FROZEN_READONLY_DATASETS["financial_statements"]`：决策、原因、三条 limitation、`forbidden`；
- `LEGACY_DATASETS`：`daily_k` / `daily_k_10d` / `adjustment_factors` 各自的存疑原因。

**数据库侧**（`MarketWarehouseService.register_legacy_datasets()`，幂等）：

- 3 个已有数据集 `status` → `legacy`，`quality_json.legacy` 写入原因与决策编号；
- `financial_statements` **原本在 `market_datasets` 里没有任何登记行** → 补一行
  `legacy_frozen_readonly`，让它出现在数据集清单里。

**可查询**（`dataset_registry()`）：把代码侧声明与实际记录并列，并自动列出 problems。
当前把它跑出来是：

```
sync_run_count: 0
problems:
  - daily_k 的 schema_version=market_daily_v1 落后于当前常量 market_daily_actions_v2
  - daily_k 登记为 legacy：…无对应 sync run
  - daily_k_10d 同上
  - adjustment_factors 登记为 legacy：无对应 sync run；质量报告含 1 条重复与 3 条同日多事件
  - market_sync_runs 为 0 行：现有数据集不可能来自正常导入流程
```

**为什么"不可能来自正常流程"**：`_ingest_file()` 会同时写 `market_datasets` **并把对应
`market_sync_runs` 记录置为 `completed`**。0 行 run 却有 3 行 dataset，只能是迁移前灌入、
手工写入或记录被清理。**登记为 legacy 而不是重跑同步**（D10）：重跑要重新拉取 5000+ 标的的
全部历史，耗时且无正确性收益。

### 2.3 `forbidden` 变成会抛错的代码路径

`WarehouseRepository.validate_parquet(kind="financial_statements")` 现在**直接抛错**，
消息里带上决策编号与 `forbidden` 文案。这样"禁止增量更新"不再依赖读者记得。

## 3. P0-4.3：as-of 从 docstring 提升为可执行断言

`corporate_action_total_return_history()` 末尾新增两条自检：

```python
beyond = [item["date_ms"] for item in items if item["date_ms"] > end_ms]
if beyond: raise ValueError("…返回了 as-of 之后的行情行…即为未来信息泄漏。")
late_events = [ms for ms in unmatched_event_dates if ms > end_ms]
if late_events: raise ValueError("…未匹配除权事件越过了 as-of…")
```

SQL 本来就用 `date_ms<=end_ms` 与 `ex_date_ms<=end_ms` 约束住了；这两条是**最后一道自检**：
一旦有人改了查询而忘了同步，必须在这里炸掉，而不是静默泄漏未来。

测试用桩连接直接把越界行喂进去，断言它确实炸（`test_repository_asserts_no_price_row_beyond_as_of`
与 `..._no_unmatched_event_beyond_as_of`）。

## 4. 首次规则变更实战（F15 → `record_change`）

### 4.1 变更内容

| | |
|---|---|
| 字段 | `strategy/grade:cost20_test_basis` |
| 旧 | `grade(..., cost20_test=cost[-1], ...)` —— `cost[-1]` 是 `run_backtest` 的**全周期** 20bps 指标 |
| 新 | `cost20_test=segments(data.strategy_id, bars, 20, gate=gate)[-1]` —— **测试段** |
| 为什么是缺陷 | 参数名 `cost20_test` 本就写明了意图。「测试段为正、全周期为负」的好实验会被误判不合格 |
| 代码哈希 | `old 8f98dd1c2f322d56` → `new e9d59db615c3c723`（真实代码内容 sha256 前缀，可从 git 复现） |

回归守卫：`test_cost20_gate_uses_the_test_segment_not_the_full_period` 用带 `marker` 的哨兵值
区分两种口径——**修之前它红了**，说明它真的在守这个 bug，而不是事后补的绿灯。

### 4.2 治理流程实测结果

```
旧批次 b4a7243c -> closed（superseded_by=8cab31eb）
新批次 8cab31eb open：C1 治理基线（2026-09-13 起） → 变更后
停止条件是否继承：True
变更留痕：1 条挂在旧批次上
```

这条实测同时验证了 G3 的三件事：**变更留痕、旧批次自动关闭并开新批次、
新批次继承停止条件**（所以"改规则"不可能顺带放松 G8 标准）。
`cost20_test_basis@1` 提案随之 `draft → frozen`（已落地，不再是可变草稿）。

> 这是治理层建成后**第一条真正走完流程的变更**。它证明了治理不是纸面机制：
> 改门禁口径这件事，代码里确实被记了一笔，而且样本被换到了新批次。
