## 4. 三个必须知道的机制

### 4.1 事件研究的两条数据通路（`--source panel|live`）

- **panel（默认）**：读预计算面板。面板带**版本号 + 行情源指纹**（`daily_k` 行数/最大日期、
  除权行数/最大除权日）；**版本或指纹不一致就自动重建**（`run_fields` 内部会做）。
  改了面板 SQL **必须**同步改 `PANEL_SCHEMA_VERSION`，否则旧缓存会被当成新口径用。
- **live**：逐日 `cross_section` + `settlement_returns`（慢，52 分钟/字段）。
  **保留它只为做等价比对**——两条通路共用 `_details` 核心，所以可以逐位比。
- 改完任何一条通路，**必须**跑 `.\.venv\Scripts\python.exe scripts\verify_event_panel.py`
  （真实库抽样 12 个评估日 / 49,095 个单元，不一致退出码 1）。

### 4.2 预注册流程（治理纪律，**先登记再跑**）

1. 在 `scripts/governance_register_limit_up_fields.py` 里加条目（字段/设计清单，
   写明样本域、对照、统计量、安慰剂、**多重检验计数**），`status: 结果尚未产生`；
2. 跑该脚本（幂等，`--dry-run` 先看计划）；
3. 再跑评价脚本；
4. 结果写文档，并把"这次看了多少条比较"如实计入下一轮的族级计数。

## 5. 下一步：**可成交性检验**（目标、做法、验收、禁止）—— **✅ 已执行完毕，结论见 `21`**

> **结果摘要（2026-09-15）**：三条口径并排跑完（1013 日 / 60,464 事件；231 秒）。
> **封单类效应全部消失并反号**：`seal_ratio` 高−低 +2.4761%（t=+10.47）→ **−0.5259%（t=−2.41）**、
> `seal_money` +1.9259%（t=+8.23）→ **−0.6061%（t=−2.82）**，均**未过族级门槛**。
> 根因已定位：那 2.48% 里 **+3.1079% 是组间隔夜跳空差**——正是「封板买不到」本身。
> 反向发现：可成交口径下**连板股跑输首板 1.8093%（t=−5.15，过 3.248）**。
> 设计登记为 `limit_up_event_study_design@v5`（`20` 号建议写 `@v6`，实际用 `@v5`——该号从未被占用）。
> 下面保留原始要求，供核对实现是否走样。

### 5.1 要回答的问题

`16`/`17` 的结论都建立在"从**评估日收盘价**算起持有 20 个交易日"上。但最强的那批
（高封单额 / 高封成比）恰恰是**封板到收盘**的股票——**当日收盘价根本买不到**。
所以现在必须回答：**把买入点挪到次日开盘、扣掉这个缺口之后，效应还剩多少？**

### 5.2 具体做法（建议）

1. **扩展面板**（`PANEL_BUILD_SQL`，版本升到 v5）新增一列，例如
   `forward_return_next_open`：
   - 起点：**T+1 的开盘价**（`lead(open_price, 1) OVER w`，注意 T+1 必须存在且 > 0）；
   - 终点：**T+20 的收盘价**（与现有 `forward_return` 同终点，便于对照）；
   - 公司行动：只计入**严格晚于 T+1**（买入日）的除权除息——
     `ex_date_ms > T+1 的日期`。**这一步最容易写错**，两种口径（含/不含 T+1 当天）
     要显式选定并写进登记条目；沿用现有"两股窗口"的处理方式（落在 K 线日 vs 落在两日之间）。
   - 同时加一列 `next_open_gap`（`T+1 开盘 / T 收盘 − 1`）——它是理解结果的关键辅助量。
2. **新开 reference**：本次是**结果口径**变更，属定义变更 → 新登记
   `limit_up_event_study_design@v6`（主检验端点写清"从 T+1 开盘起算"），
   字段沿用 `seal_money` / `seal_ratio` / `continue_day_cnt`（字段定义没变）。
3. **族级计数**：封单族此前已看过 40 条（`16` 的 20 + `17` 的 20）→ 本轮族级门槛据此算
   （约 60 条 → 先算准再写进登记条目，不要凭感觉）。
4. **跑**：
   ```powershell
   .\.venv\Scripts\python.exe scripts\run_limit_up_event_study.py --field seal_ratio `
     --family-prior-statistics 40 --out data\exports\event-study\<日期>-next-open
   ```
   （`--family-prior-statistics` 修好之前，显式传数字；修好后按字段传。）
5. **对照与判读**（建议同时报这三组）：
   - `close_T → T+20 close`（现有口径，作为对照）；
   - `T+1 open → T+20 close`（可成交口径，**主检验**）；
   - `T+1 open → T+1 close`（次日日内，用来看缺口是否就是全部效应）；
   并报 `next_open_gap` 在高/低封成比两组间的差异——**这就是"买不到"的量化**。

### 5.3 验收标准

- **结果必须可比**：同一样本域（1013 个评估日 / 60,464 个事件）下三种口径并排给出；
- **必须诚实回答"还剩多少"**：如果效应在 T+1 开盘口径下消失或反号，就照实写
  "该发现不可成交"，并据此收紧 `16`/`17` 的结论表述（不要护着之前的结论）；
- 面板改了必须 `PANEL_SCHEMA_VERSION++`，且 `verify_event_panel.py` 仍须判"等价 ✅"
  （live 通路也要同步支持该口径，否则无法比对）；
- 新 reference 先在**看到数字之前**登记。

### 5.4 禁止

- 禁止为了让效应活下来而改终点（T+20 → T+10/T+5）或改起点（T+1 开盘 → T+1 均价）；
  要换就是新 reference + 新预注册；
- 禁止把"封板当日买不到"这件事含糊过去（例如拿 T 收盘价当成交价还宣称可成交）；
- 禁止跳过族级多重检验计数。

## 7. 环境与工具坑（**踩过的，逐条都值钱**）

| 坑 | 现象 | 做法 |
|---|---|---|
| **PowerShell 5.1 会毁 UTF-8 源码** | `Get-Content \| Set-Content` 按 GBK 解码 → 中文乱码且**不可逆**（只能 `git checkout` 重做） | **绝不用 PowerShell 读写/改写源码与文档**；文本变换用 Python（显式 `encoding='utf-8'`、`newline='\n'`）或 PowerShell 7；PS 5.1 读文件至少 `-Encoding UTF8`。守卫：`tests/unit/test_text_encoding_guard.py`（查私用区 U+E000–U+F8FF 与 U+FFFD） |
| **PowerShell 会啃内联 Python** | `python -c "..."` 里的引号/f-string 被 PS 解析器拆坏 | 超过一行就写成 `.py` 脚本再跑（`.cache/` 下临时脚本，已被 gitignore） |
| **DuckDB 参数化插入极慢** | 约 2–7 毫秒/行（2400 行要 7–17 秒），与索引/事务/磁盘无关 | 测试夹具**小 + `scope="module"`** 复用；大批量用 `CREATE TABLE AS SELECT` 而不是逐行 INSERT |
| **`tracemalloc` 会污染墙钟** | 把 37 秒的跑拖成 973 秒（26×），据此会误判"只快了 3.25×" | 测性能时关掉 tracemalloc/逐行 profiler；**微观隔离测量不能外推长跑**，要在真实规模上量 |
| **沙箱里管道 Native 程序输出可能被拒** | `python ... \| Select-Object` 报错 | 用 `> file 2>&1` 重定向后再读文件 |
| **git 推送必须走代理 7890** | 直连 `Failed to connect ... after 21s` / `Recv failure: reset`；`Invoke-WebRequest https://github.com` 返回 200 ≠ git 能连（git 不读 WinINET） | `$env:HTTPS_PROXY='http://127.0.0.1:7890'`；**7891 不是 HTTP 代理口**（用了连不上）；不要改全局 git config |
| **多行 commit message 会被 PS 弄坏** | 引号被吞 | 写成文件后 `git commit -F <file>` |
| **DuckDB `CREATE OR REPLACE TABLE` 不回收旧块** | 面板重建后文件翻倍（383→767 MB） | 构建后 `CHECKPOINT` |
