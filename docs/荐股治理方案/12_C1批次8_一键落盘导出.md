## 1. 产物长什么样（真实导出，未修饰）

`daily.md` 的结构：

| 节 | 内容 |
|---|---|
| 0. 本次导出范围 | 日期（Asia/Shanghai）、当前批次与状态、样本计数、**空样本时的明确说明** |
| 1. 当日候选与档位 | 标的 / 方向 / 把握度 / **档位** / **档位理由** / 策略引用 |
| 2. 建议卡明细 | 三情景概率与来源、陈述（fact/inference）与证据编号、失效条件、观察哨、**参数哈希与证据哈希**、模型配置 ID 与提示词版本、批次、双轨状态 |
| 3. 策略实验 | 标的 / 策略@版本 / 级别 / 原因 / 参数哈希 / 数据快照 sha256 |
| 4. 双轨独立结算 | 每条建议的两条轨：方向、状态、命中、二元 Brier、是否弃权、结算区间 |
| 5. 治理状态 | 进行中批次、**预注册停止条件**、预注册台账（含 `trial_count`）、**规则变更留痕** |
| 6. 常驻披露 | 幸存者偏差、探索性结果不得用于判定、变更必须走 `record_change` |

`batch.json` 的审计块（这是"审计用"的实际含义）：

```json
{
  "generated_by": "user_clicked_export",
  "background_timer": false,
  "audit": {
    "params_hashes": [...], "evidence_hashes": [...],
    "model_profile_ids": [...], "prompt_versions": [...],
    "data_snapshots": [{"experiment_id": ..., "sha256": ..., "basis": "corporate_action_total_return_v1"}],
    "rule_changes": [...], "hypotheses": [...], "batches": [...]
  }
}
```

`"background_timer": false` 是**特意写进产物**的：它让"这份数据不是后台定时产出的"成为文件自身的属性，
而不是一句口头承诺。

## 2. 界面（导航第 16 项：治理与落盘）

`frontend/src/pages/Governance/`，四块：

1. **一键落盘** —— 日期输入（留空=今天）+ 「导出当日测试数据」按钮；导出后当场显示范围、四项计数、
   以及"样本为空：是/否"；空样本时给 `warning` 提示而不是 `success`（**不让人误以为导出了东西**）。
2. **历史导出** —— 列出已有目录与文件大小。
3. **当前评估批次** —— 批次号/名称/状态/开始时间、**预注册停止条件表**、成员统计。
   没有进行中批次时明确写出"没有批次时拒绝登记建议与实验"。
4. **预注册台账 / 规则变更留痕 / 历史批次** —— 三张表，含 `trial_count`（多重检验计数）与
   `superseded_by`（批次接替链）。

前端跑的是 `vite` dev（`scripts/start_frontend.ps1` → `npm run dev`），新页面与路由**自动热更新**，
不需要重新构建。

## 3. 本次顺手抓出的两处漂移

### 3.1 doc_lint 新增第 4 项检查（导航清单）

加「治理与落盘」导航项的那一刻，说明书里的「左侧导航从上到下依次是：…（共 15 项）」就变成了错的——
而原有的三项检查（路径 / 版本号 / 常量）**都抓不到**这种漂移。

所以给 `scripts/doc_lint.py` 加了第 4 项：从 `Layout/index.tsx` 抽取 `NavLink` 标签序列，
与说明书那句导航清单**逐项同序**比较。首跑立刻报出：

```
## 导航清单：1 条
  - 说明书导航清单与实际不一致：文档 15 项、代码 16 项
```

修完为 0。**这正是 D15 想要的：把"人会忘"换成"机器会拦"。**

### 3.2 换行翻译导致报告字节数说谎

`Path.write_text` 在 Windows 上默认把 `\n` 翻成 `\r\n`，于是**接口报告的字节数与磁盘实际不符**
（`daily.md` 报 3482、实际 3555，差值恰好等于行数）。已显式 `newline="\n"`，
并加断言"报告的 `bytes` 必须等于磁盘 `stat().st_size`"。

顺带的好处：产物现在**逐字节可复现**，不再依赖运行平台。

## 4. 诚实性检查清单（这套产物凭什么可信）

| 检查 | 实现 |
|---|---|
| 不会偷偷后台跑 | 模块内**不得出现** `threading/asyncio/schedule/Timer/apscheduler/cron`——写成静态测试，出现即红 |
| 接口只由点击触发 | 只有 `POST /test-run-export` 会落盘；`GET /test-run-exports` 只读；测试断言导出服务在接口层只被调用一次 |
| 空样本不装样子 | `sample_is_empty` 写进三份产物；`daily.md` 写明"不代表系统故障"与可能原因 |
| 范围不串批 | 按批次导出时只取该批次的 `batch_members`；测试构造两个批次的建议，断言不互相泄漏 |
| "当日"按上海时区 | `created_at` 是 UTC，"当日"按 Asia/Shanghai 判定；测试用 `2026-09-13T20:00Z`（=CST 09-14）验证 |
| 不含秘密 | 只导出台账字段；不读 `.env`、不读 `data_cache`、不含模型隐藏推理 |
| 常驻免责 | 三份产物都带"研究参考，不构成投资建议"，`daily.md` 另带三条常驻披露 |
