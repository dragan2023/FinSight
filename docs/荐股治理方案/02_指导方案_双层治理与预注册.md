# 方案 C · 双层治理与预注册（推荐）

> **一句话**：把荐股拆成"确定性层提名、LLM 层只能否决、治理层保证过程可审计"三层结构，
> 并把现在的 4 份人工文档升级为数据库里的**预注册台账**，使规则在评估期内无法被事后改写。
>
> **它回答的问题**：这套系统能不能产出**可审计、可复现、可证伪**的荐股结论——
> 并且能分别回答"确定性信号本身有没有优势"和"LLM 的裁决是加分还是减分"。

---

## 1. 定位

方案 C 的核心判断是：**FinSight 缺的不是算法，是治理。**

现有代码其实已经把握住了两条关键原则：

1. **LLM 只能降级不能升级** —— `_enrich_card()` 在无候选时强制改写为 `wait`，
   abstain 保持 abstain（`advisor/graph.py:696-704`）；`_recommendation_tier()` 明确声明
   "LLM 的措辞不能改变本函数结果"（`output_models.py:146-149`）。
2. **双轨登记** —— `advice_ledger`（执行建议轨）与 `research_predictions`（研究预测轨）
   已经分离，schema v28/v29/v30 还预留了 `strategy_ref_json`、`strategy_forecast_json`、
   `tier_snapshot_json`、`params_hash`、`prompt_version`、`model_profile_id`、`evidence_hash`。

**但这两条原则缺少使之生效的机制**：

- "规则在评估期内不得改写"目前只是文档里的一句话，**没有任何代码阻止你改**。
- 治理规则散落在 4 份方案文档 + 1 份边界文档 + 1 份方法卡里，而且**已经失准**：
  验证方案引用的 11 条路径中 9 条不存在；方法卡写 v1 而代码是 v2；
  自称"唯一口径"的边界文档，其上位依据已被删除（F10）。
- LLM 的裁决结果被门禁**压制掉了**，而不是**记录为一条独立轨道**。于是你无法回答
  "如果把 LLM 换成抛硬币，结果会更好还是更差"。

方案 C 就是补上这三件事。

## 2. 三层结构与一句话分工

```
治理层（预注册台账 / 冻结 / 批次隔离 / 独立结算 / 停用规则）
   └─ 保证：规则在评估期内不可改写，结论可复现、可证伪
LLM 层（顾问链：解释、反证、风险叙述、可否决）
   └─ 权限：只能把档位往下压，永远不能往上抬
确定性层（候选池 + 因子/策略信号）
   └─ 权限：只能提名，不能决定最终档位
```

**关键约束**：方向与档位的**上限**由确定性层决定，**下限**由 LLM 层决定，
最终结果取两者中更保守的一个。这条规则使 LLM 的风险控制能力可用，
同时使其无法制造虚假的乐观。

## 3. 目标与非目标

### 目标

1. 每一条建议都能回答"**当时为什么给这个档位**"——从数据库查询，而不是靠回忆。
2. 评估期内**程序性拒绝**规则变更；变更即开启新批次，旧样本不合并。
3. **两条轨独立结算**，从而量化 LLM 裁决的边际贡献（正、负或零）。
4. 明确停用条件预先写死，达标即停，不延长、不降标准。
5. 用预注册台账取代散落文档，使口径只有一个来源。

### 非目标

- 不追求一次性建成的全市场因子库（那是方案 B 的深度；C 复用 B 的 `screener/` 作为 C2）。
- 不改 `docs/API与数据使用边界.md` §4 的六条保留红线。
- 不承诺收益。输出是**校准的概率 + 明确的失效条件 + 可复现的过程**。

## 4. 阶段改动

### C1 · 治理机制落地（约 3 周）

**这是方案 C 的核心交付，也是它区别于 A/B 的地方。**

新增 4 张表（Schema 从当前 v31 继续递增）：

| 表 | 作用 | 关键字段 |
|---|---|---|
| `hypothesis_registry` | **预注册台账**：任何候选规则/因子/策略进入评估前必须登记 | `id, kind, name, definition_json, direction, params_json, params_hash, submitted_at, frozen_at, status(draft/frozen/retired)` |
| `evaluation_batches` | **评估批次**：一批冻结规则 + 预注册分析计划 + 停止条件 | `id, name, plan_json, stop_criteria_json, started_at, closed_at, status(open/frozen/closed), verdict_json` |
| `batch_members` | **批次隔离**：把每条建议/实验/预测绑定到唯一批次 | `batch_id, artifact_kind, artifact_id` |
| `rule_change_log` | **变更留痕**：评估期内每次规则改动都被记录并触发新批次 | `id, batch_id, changed_at, field, old_hash, new_hash, forced_new_batch_id` |

配套的程序性约束（**这是"治理"从文档变成代码的关键**）：

1. 处于 `frozen` 状态的批次，其 `hypothesis_registry` 条目的
   `definition_json` / `params_json` **不可更新**——写入即报错。
2. 若确需变更，唯一合法路径是 `rule_change_log` 记录变更并**自动开启新批次**，
   旧批次置为 `closed`。
3. 结算与统计**只按批次聚合**，跨批次合并需要显式标注且不得用于判定。
4. `advisor/graph.py` 在登记建议时强制写入 `batch_id`，缺失则拒绝登记。

同时完成 C1 的其余两项：

- **P0 全部完成**（见 01 号文档）；特别是 P0-1 未复权基率与 P0-2 测试网。
- **双轨独立结算**：`advice_ledger` 已有 `strategy_forecast_json` 与 `tier_snapshot_json`。
  C1 要做的是让**策略原始信号**与**AI 裁决结果**各自成为可结算的独立记录，
  而不是把 AI 结果压制进 `wait` 就丢掉。结算后输出一张对比表：

  | 指标 | 策略轨 | AI 裁决轨 |
  |---|---|---|
  | 方向命中率 | … | … |
  | Brier 分数 | … | … |
  | 概率校准 | … | … |
  | 等待/拒答比例 | … | … |

  **LLM 的边际贡献 = 两轨差值。**这是判断"要不要继续用 LLM 参与决策"的唯一诚实依据，
  也是方案 A/B 都没有回答的问题。

### C2 · 候选池自动化（约 2–3 个月）

接入方案 B 的 `screener/` 与最小因子集，用于**产生候选**而非决定方向：

- 每日输出全市场排序（标注为"候选池"），取前 N 只进入 C1 的评估流程。
- 打分全部基于**本地 DuckDB**，不联网、不调用付费 API——满足"付费 API 不得后台自动调用"红线。
- 数据同步（`sync_full_market_history.py`）**保持人工显式动作**。
- 因子集从最小可用开始（流动性 + 动量 + F-Score + Z-Score），
  每个因子按方案 B 的 5.1 登记入册。

### C3 · 前向批次与判定（持续 12 周 / 6 个月）

- 每 12 周为一个 `evaluation_batches` 单元，结束时按预注册的停止条件出判定。
- 三层判定互不混淆：**运行可用性 / 预测有效性 / 真实盈利能力**。
- 真实盈利仍以券商成交记录为准（系统不接券商，遵守红线）。

## 5. 治理机制（核心交付，逐条可执行）

| # | 机制 | 落点 | 强制执行方式 |
|---|---|---|---|
| G1 | 预注册 | `hypothesis_registry` | 未登记的策略/因子不得进入候选生成 |
| G2 | 评估期冻结 | `hypothesis_registry.status='frozen'` | 冻结期 UPDATE 直接抛错 |
| G3 | 变更即新批次 | `rule_change_log` | 变更自动 `closed` 旧批次并开新批次 |
| G4 | 批次隔离 | `batch_members` | 统计只按批次聚合；跨批次合并需显式标注 |
| G5 | 双层权限 | `_enrich_card()` + `_recommendation_tier()` | 档位取两层中更保守者；LLM 无法抬档 |
| G6 | 双轨独立结算 | `advice_ledger` 策略轨 / AI 轨 | 两轨各自结算，输出边际贡献 |
| G7 | 审计留痕 | 既有 `params_hash`/`evidence_hash`/`prompt_version`/`model_profile_id` | 每条建议必须齐备，缺失拒绝登记 |
| G8 | 预先写死的停用条件 | `evaluation_batches.stop_criteria_json` | 达标即停，禁止延长或降低标准 |
| G9 | 单一口径来源 | registry 成为唯一权威 | 既有文档改为由 registry 生成/校验（修 F10） |
| G10 | 红线条不放松 | 不做自动任务、不接券商、付费 API 不自动调用 | 代码层保持 |

### G8 的具体停止条件（必须在批次开始前写入）

| 检查点 | 停止条件 | 判定 |
|---|---|---|
| 第 10 个交易日 | 无任何 `trial_buy_signal`，或关键工具频繁失败 | 当前版本不可用 |
| ≥30 条已结算 | 方向命中率 95% 置信区间包含 50% | 无方向优势 |
| ≥60 条且满 12 周 | 未优于简单基准，或真实净收益为负 | 正式停用 |
| 任意时点 | AI 裁决轨显著**劣于**策略轨 | 移除 LLM 的方向权限（退化为纯解释） |
| 任意时点 | 走查/实盘与回测偏离超阈值 | 暂停并排查实现差异 |

第四行是方案 C 独有的：**它承认 LLM 可能有害，并预先定义好如何体面地把它降级。**

## 6. 验收标准

| 维度 | 可证伪的判据 |
|---|---|
| 冻结有效 | 对 `frozen` 批次的规则发起 UPDATE，必须失败；测试覆盖此路径 |
| 批次隔离 | 跨批次合并统计必须被拒绝或显式标注；测试覆盖 |
| 双层权限 | 构造"LLM 想给 accumulate 但确定性层为 wait"的输入，最终档位必须为 wait |
| 档位天花板 | 无 `forward_calibration`/`portfolio_validation` 时，任何输入都不得产出 `recommended` |
| 双轨结算 | 同一批建议能输出策略轨与 AI 轨的两套指标及差值 |
| 审计完备 | 每条建议都带 `batch_id` + `params_hash` + `evidence_hash` + `prompt_version` + `model_profile_id` |
| 可复现 | 同一批次的候选与信号可确定性重放 |
| 口径唯一 | 文档中引用的路径与版本号全部真实存在且与代码一致 |

## 7. 里程碑与工作量

| 阶段 | 工期 | 交付物 | 依赖 |
|---|---|---|---|
| C1 治理落地 | 3 周 | 4 张新表 + 冻结/批次/留痕的程序约束 + P0 全部 + 双轨独立结算 | P0-1/P0-2 |
| C2 候选池自动化 | 2–3 个月 | `screener/` + 最小因子集 + 每日候选池 | C1、本文附录的因子层 |

**C1 三周即可产出第一个"可审计的荐股结论"**——它先回答"系统可用吗、证据链通不通"，
C2/C3 才回答"有没有优势"。两者不得混为一谈。

## 8. 风险与失效条件

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| **流程负担过重**，实际执行时绕过冻结 | 中高 | 治理形同虚设，退化为纯人工流程 | G2/G3 必须做成**程序拒绝**而非提醒；否则本方案无价值 |
| 过度工程：C2 之前就建大因子库 | 中 | 时间被吃掉 | C1 不依赖因子，先拿治理与双轨结论 |
| LLM 边际贡献为负 | 中 | 需移除 LLM 方向权限 | 这正是 G8 第四行的预设路径，提前接受 |
| 统计功效仍不足 | 中 | 12 周无定论 | C2 上线后样本量显著高于纯人工候选 |
| 幸存者偏差 / `disclosed_at_ms` 不可靠 | 中 | 历史统计失真 | 见附录 A.0 的验证项 |
| 2026-09-02 之后的重构无测试保护 | 高（当前） | 改治理代码引入回归 | P0-2 必须先完成 |

## 9. 附录：因子层与统计规范（C2 使用）

C2 引入横截面因子排序时必须遵守下列规范。本节吸收了原先独立的因子方案，不再单列文档。

### A.0 必须先确认的三件事

1. **财务因子不列入第一期**（决策 D1）。`financial_statements` 的 26 个字段既没有 ROA 指标，
   也没有 Z-Score 需要的 `retained_earnings` 与 `market_value_equity`，所以"复用已实现的
   F-Score / Z-Score"**不能直接成立**。第一期只用「量价 + 流动性」因子。财务因子的前置条件
   是先落实 `01` 号文档 P0-4.1(a)：重建一个**可复现**的财务数据集。
2. **幸存者偏差程度必须量化。** `daily_k` 有 5556 个标的，若其中包含已退市/长期停牌证券，
   偏差较小；若只有当前存续标的，则所有历史统计都会高估收益。

   ```sql
   -- 最后交易日远早于 2026-09-04 的标的数 = 疑似退市/长期停牌
   SELECT count(*) FROM (
     SELECT thscode, max(date_ms) AS last_ms FROM daily_k GROUP BY thscode
   ) WHERE last_ms < (SELECT max(date_ms) FROM daily_k) - 30*86400000;
   ```

3. **`disclosed_at_ms` 的可用性与一致性。** 抽查若干标的确认它真实反映披露时间而非回填时间；
   若不可靠，point-in-time 退化为"`period_end_ms` + 固定滞后"，并必须在报告中披露。

### A.1 因子准入（先于任何回测）

一个因子进入研究池前必须满足：

1. **先验逻辑**：能用一句话说明经济/行为学机制，不接受纯数据挖掘产物。
2. **数据可用性**：所需字段覆盖度达标，且**时点可得**（不得使用未披露数据）。
3. **换手率上限**：预估换手对应的成本不得超过收益量级。
4. **登记入册**（写入 `hypothesis_registry`）：含定义、方向、参数、提交日期。
   **登记后不得改名或改定义**——变更视为新因子，否则多重检验计数会失真。

### A.2 预注册与多重检验校正

- 每个因子在评估前写下：预期方向、预期 IC 量级、评估窗口、判定门槛。完成后只能追加结论。
- **统计全部尝试过的因子数量（含放弃的）**，而非最终保留数量。
- 显著性采用 Deflated Sharpe Ratio 或 FDR 控制；报告须同时给出"未校正"与"校正后"的差异。

### A.3 走查与样本隔离

- 开发 / 验证 / 测试三段，**未来数据不得进入信号计算**。
- 参数只能在训练段拟合；**测试段只用一次，用后即封存**。
- 报告样本外净值，而非全样本净值。

### A.4 成本与可执行性

- 单边成本默认 10 bps，同时展示 5 / 10 / 20 bps 敏感性（沿用既有约定）。
- **必须建模**涨跌停不可买入、停牌不可交易、T+1 约束，否则回测不可执行。
- 报告须包含换手率与"无法成交比例"。

### A.5 停用规则（预先写死）

| 触发 | 动作 |
|---|---|
| 样本外 IC 均值 95% 置信区间包含 0 | 因子停用 |
| 组合净收益扣除成本后不显著优于基准 | 组合停用 |
| 走查期间 IC 符号翻转 | 因子降级并复核先验逻辑 |
| 纸上交易与回测偏离超预设阈值 | 暂停并排查实现差异 |

### A.6 代码落点

| 模块 | 职责 |
|---|---|
| `backend/app/screener/` | 时点横截面：`cross_section(date_ms, universe, factors, ...)`，**固定 SQL 模板，禁止调用方传入 SQL 片段**；股票池规则显式化；复用 `market_warehouse/repository.py:203+` 的公司行动感知序列并对 `ex_date_ms` 强制 as-of 截断 |
| `backend/app/factorlab/`（后置） | 因子定义、Rank IC 时序与 IR、分位组合、走查、显著性检验 |
| `backend/app/portfolio/backtest.py` | **已存在但从未被引用**，含 `run_portfolio_backtest()` 与 `excess_vs_cash_pct` 等指标——组合层净值与回撤直接接它，不另写一套 |

**关键约束**：因子打分**全部基于本地 DuckDB**（本地、免费、不联网），数据同步保持人工显式动作，
以满足"付费 API 不得后台自动调用"的红线。

## 10. 明确不做

- 不做自动任务、不接券商、不下单、不推送（既有红线，C 不放松）。
- 不把"候选池"称为"买入清单"；输出一律标注研究参考、不构成投资建议。
- 不允许 LLM 提升档位；不允许在评估期内改写规则。
- 不用两周小样本宣称长期有效。
- 不为得到更好统计而修改已封存的预测、删亏损记录、或改写到期规则。
