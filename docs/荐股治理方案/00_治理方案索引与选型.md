# FinSight 荐股治理方案 · 索引与选型

## 1. 本文档集要解决的问题

FinSight 目前**已经有一套完整的荐股链路**（选股 → 策略门禁 → 顾问裁决 → 台账 → 结算 → 评审），但它在设计上被四层门禁锁死，且运行库里没有任何使用痕迹，所以今天无论问哪只股票，输出必然是「等待」或「拒答」。

本文档集给出三套**不同的终局形态**，用于把"能产出带条件的观点"升级为"具备科学荐股能力"。三套方案的第一阶段（`01` 号文档的 P0 项）完全相同，分叉点只有两个：**信号从哪里来**，以及**治理做到多重**。

## 3. 三套方案一览

| 维度 | 方案 A · 保守加固 | 方案 B · 因子工厂 | 方案 C · 双层治理与预注册 |
|---|---|---|---|
| 一句话 | 把已有门禁喂饱，不加新引擎 | 用横截面因子取代 LLM 作为信号源 | 确定性排序出候选，LLM 只能降级；核心交付是治理机制 |
| 信号来源 | 现有 2 个确定性策略 + 人工候选池 | 全市场因子 IC/IR 排序 | 因子排序出候选，LLM 仅可否决 |
| LLM 角色 | 裁决 + 叙述 | 仅解释与风险叙述 | 仅降级（现状已如此，只是没有治理） |
| 治理强度 | 中：预注册评估批次 + 人工前向观察 | 高：统计检验 + 多重检验校正 | 最高：预注册台账 + 冻结期 + 批次隔离 + 审计留痕 |
| 治理载体 | 4 份人工流程文档 | 因子准入清单 + 走查报告 | **数据库内的预注册台账（成为唯一口径）** |
| 新增代码 | 小（约 500 行） | 大（约 4000 行） | 中（约 1500 行 + 治理表结构） |
| 首个可用性结论 | 10 个交易日 | 3–4 个月 | 3 周（C1）；3 个月（C2） |
| 首个统计结论 | 12 周 / 60 条预测 | 6–9 个月 | 12 周 |
| 能否回答"全市场今天该看哪几只" | **不能**（每天 ≤3 只，人工选） | 能 | 能 |
| 主要风险 | 统计功效极低；12 周结论大概率"不显著" | 找不到显著因子，最终产出"无优势" | 流程负担；可能过度工程 |
| 失败时的产出 | 明确判定"当前版本不可用" | 明确判定"无显著优势" | 可审计地停用并冻结批次 |
| 适合的目标 | 想最快看到系统真的产出买入信号 | 目标是可持续的量化排序系统 | 目标是可审计的科研资产 |

## 4. 三套方案的共同部分

`01_通用前置条件与P0修复.md` 里的 P0 项对三套方案**都是硬前置**，不做完任何一套都无法成立：

1. **P0-1** 修未复权的概率基率（F4）——唯一同时污染概率与仓位的正确性缺陷。
2. **P0-2** 为推荐链建立回归测试网（F9）——否则改门禁是在无网高空作业。
3. **P0-3** 打通候选池数据通路（F5）——需要固定 SQL 模板与因子层，禁止任意 SQL。
4. **P0-4** 修数据溯源（F7/F8）——财务库不可复现、未来除权日会泄漏未来信息。
5. **P0-5** 对齐文档口径（F10）——否则按文档改代码会找错文件。
6. **P0-6** 收尾仓库卫生（备份提交与 `.gitignore` 已完成，剩 untrack 与 `finsight.db` 去留）。

## 5. 一条所有方案都必须绕开的红线冲突

**"全自动日更荐股"与既有红线「付费 API 不自动调用」存在张力。**

既有边界（`docs/API与数据使用边界.md` §4）规定：付费调用只能发生在用户主动发起的会话或任务中，绝不后台定时触发；免费 RSS 轮询是唯一例外。

因此**自动化荐股方案的正确形态是**：打分与排序建立在**本地 DuckDB 仓库**之上（本地、免费、不联网），而数据同步（`sync_full_market_history.py` 等）**保持为人工显式动作**。任何"后台自动拉同花顺、自动生成荐股"的设计都会撞红线，方案 B / C 均按前者设计。

同时，既有红线要求筛选结果**一律标注为"候选池"而非"买入清单"**，三套方案的输出命名都遵循此约束。

## 6. 选型建议

**如果只能选一套：选方案 C，按 C1 → C2 → C3 分阶段推进。**

理由：

1. 你给的目标是"**真正具备科学荐股功能**"。方案 A 的终局是受控人工实验，12 周最多产出 60 条样本，统计功效不足以支撑"科学"二字的承诺——它能证明"系统可用"，不能证明"系统有优势"。
2. 方案 B 把 LLM 移出决策路径，方向正确，但它丢掉了 FinSight 已有的资产：逐条证据可追溯、缺口可见、拒答机制、双轨台账。这些恰好是"可审计"的基础。
3. 方案 C 的独特之处在于它**把治理机制本身做成交付物**：预注册台账取代现在散落且已失准的 4 份人工文档（F10），使"当时为什么给这个档位"变成可查询的数据而不是回忆。这一条直接修掉了现状里最根本的科研缺陷——**规则可以在看到结果之后被改写**。

**什么时候选 A**：你只想尽快确认"这套东西到底能不能吐出一个买入信号"。1–2 周即可证伪，成本最低。

**什么时候选 B**：你有量化基础，且已决定不让 LLM 参与任何决策，只把它当解释器。

## 8. 与既有红线的关系

三套方案**均不修改** `docs/API与数据使用边界.md` §4 的六条保留红线：不接券商、不下单、不通知；不承诺收益；不伪造证据；不用爬虫；Key/预签名 URL/隐藏推理不落盘不外传、付费 API 不自动调用；不提供持牌投顾表述。

科学荐股的实现方式是**输出校准过的概率、明确的失效条件与可复现的过程**，而不是更强的措辞。这一点与现有 `_recommendation_tier()` 的设计意图一致——它刻意不允许 LLM 措辞抬高档位。
