## 1. 核心缺陷与修法

### 1.1 缺陷（实查定位）

```python
# advisor/graph.py（批次 5 之前）
card = self._enrich_card(card, pack, conflicts=conflicts)   # ← 就地改写
...
entry = self._ledger.register(card.model_dump(), ...)        # ← 登记的是改写后的卡
```

`_enrich_card()` 会做三件改写方向/把握度的事（`graph.py:688-707`）：

1. 有未解决的策略冲突且方向非 `abstain` → **强制 `wait`** + `very_low`；
2. 候选为空且方向非 `abstain` → **强制 `wait`** + `very_low` + 清空 `strategy_refs`；
3. 候选存在 → 把握度**封顶 `medium`**。

于是 `advice_ledger.card_json` 里只剩被门禁修剪过的结果。**用改写后的卡片做"AI 轨"，
等于拿被治理层修剪过的结果去评价治理层**——这正是 `02` 号文档说的"LLM 的裁决结果被门禁
压制掉了，而不是记录为一条独立轨道"。

### 1.2 修法

```python
# advisor/graph.py（现在）
raw_verdict = card.model_dump()        # 门禁改写之前的原始 LLM 裁决
card = self._enrich_card(card, pack, conflicts=conflicts)
...
entry = self._ledger.register(..., raw_verdict=raw_verdict)
```

`AdvisorLedger.register()` 把原始裁决写入 `advice_ledger.llm_verdict_json`，
并调用 `DualTrackLedger.seal()` 封存两条轨。**`raw_verdict` 缺省为 None 时，AI 轨记为
"不可结算"（`eligible=0`）并写明原因——绝不用被改写的卡片冒充 AI 轨。**

> 守卫测试 `test_ai_track_records_the_pre_gate_verdict_not_the_gated_card` 就是这条：
> 传入一张已被改写成 `wait` 的卡片 + `direction="accumulate"` 的原始裁决，
> 断言 **`entry["direction"] == "wait"` 而 AI 轨 `direction == "accumulate"`**。

## 2. 两条轨的定义（都是"原始"的）

| 轨 | 来源 | 为什么是这个 |
|---|---|---|
| `strategy` | 候选策略实验的 `signal_snapshot`（`next_position`）+ 由该实验净值曲线非重叠窗口估计的经验概率 | 确定性层**只能提名**，不能决定最终档位；它自己的那次提名必须单独留档 |
| `ai` | **门禁改写之前**的 LLM 裁决（`direction` / `confidence` / `research_prediction`） | 见 §1.1 |

**两轨共享同一个 `as_of_date` 与到期窗口**——否则差值比较的不是同一个市场区间，毫无意义。
`as_of_basis` 记录日期来源（`candidate_signal_snapshot` 或 `registration_date`），便于事后核验。

**弃权是合法一等状态**：没有候选信号时策略轨记 `abstain` 且 `eligible=0`；
AI 说 `wait`/`hold`/`abstain` 时方向命中率为 `None`。
两者都计入**等待/拒答比例**，都**不**计入方向命中率。

## 3. 结算口径与指标

- **数据源**：`corporate_action_total_return_history()` + `total_return_closes()`（P0-1），
  口径标记 `basis: "local_total_return_close"`。**不联网**。
- **窗口**：`as_of_date` 起第 `horizon_days` 个**已观测交易日**（不是自然日），
  窗口未齐备时返回 `data_unavailable` 并说明"已观测 x/y"，**不猜、不插值**。
- **结果分类**：`up` / `flat` / `down`，阈值取该轨自己的 `return_threshold_pct`。
- **指标**：

| 指标 | 定义 | 两轨可比性 |
|---|---|---|
| 方向命中率 | `accumulate` → 命中 = `up`；`avoid`/`reduce` → 命中 = `down`；其余为弃权 | ✅ |
| 95% 置信区间 | **Wilson 区间**（小样本比正态近似可靠） | ✅ |
| 二元 Brier | 事件固定为「到期收益 ≥ +阈值」，因此**两轨可直接比较** | ✅ |
| 三分类 Brier | AI 轨有完整 `p_up/p_flat/p_down` 时附加给出 | 仅 AI 轨 |
| 等待/拒答比例 | 弃权数 / 已结算数 | ✅ |

- **已结算的轨道不可改写**：`track_settlements_settled_immutable` /
  `_no_delete` 两个触发器直接拒绝（`02` 号文档 §10「不为得到更好统计而修改已封存的预测」）。
  改结论会同时作废两轨的差值，所以这不是保守，是必要条件。

## 4. 边际贡献报告与治理联动

`DualTrackLedger.margin_report()` → 两轨对比表 + `marginal_contribution`（`AI − 策略`）：

```
{ "tracks": { "strategy": {...}, "ai": {...} },
  "marginal_contribution": { "hit_rate": +0.10, "binary_brier": +0.04, "abstention_rate": ... },
  "sufficient": true|false,
  "verdict_note": 样本不足时的明确拒绝 }
```

`evaluate_stop_criteria()` 把 `02` 号文档 §5 的 **G8 预注册停止条件**里
**纯统计的两条**程序化：

| 条件 | 判据 | 实现 |
|---|---|---|
| `settled_30` | 任一轨 ≥30 条已结算且方向命中率 95% 区间**包含 50%** | ✅ 自动判定 |
| `ai_track_worse` | AI 轨命中率 95% 区间**整体低于**策略轨 | ✅ 自动判定 |
| `day_10` / `settled_60_weeks_12` / `drift` | 含日历、成交与实现差异，**不是纯统计量** | ❌ 明确列进 `not_evaluated`，**不假装能自动判** |

最后一条是刻意的：「工具频繁失败」「实盘与回测偏离超阈值」需要人看，
把它们硬编码成统计判据只会制造虚假的自动化。

## 5. 验收

| 验收维度 | 判据 | 测试 |
|---|---|---|
| AI 轨是**原始**的 | 门禁改写后仍记原始方向 | `test_ai_track_records_the_pre_gate_verdict_not_the_gated_card` |
| 不拿改写卡冒充 | 无 `raw_verdict` → `eligible=0` + 原因 | `test_ai_track_is_ineligible_without_a_raw_verdict` |

| 窗口不足不猜 | `data_unavailable` + "已观测 x/y" | `test_settlement_refuses_when_the_horizon_window_is_incomplete` |

## 6. 本次刻意没有做的事

1. **没有改 `AdvisorLedger.settle()`**（执行建议轨的结算）。它走同花顺前复权日 K，
   与本模块的本地总收益序列在**收益率口径上等价**（F21 已验证），所以两套口径不冲突；
   在一个批次里同时改两条结算路径会放大回归面。**统一结算基座留作后续独立变更。**
2. **没有自动结算**。结算必须由用户显式触发（`confirmed` 参数），不做后台定时——红线。
3. **没有把三个非统计停止条件自动化**（§4 已说明）。
4. **没有动任何门禁阈值**（D4）。
