### 3.3 早退测试的含义（F13–F14）

**早退测试没有证明「门禁太严」，恰恰证明门禁在正常工作。** 门禁是**过滤器**，
5556 只标的中只有少数应当成为候选。真正致命的是：**能送给门禁筛选的标的只有 3 个，
其中 1 个指数提交不了、1 个只有 13 根 K 线——池子本身不成立。**

因此：**候选池与因子层（C2）从「可选」升级为「前置必需」**，但**不允许**通过放宽阈值、
拉长回测区间或降低标准来「修复」结果（§6 红线 + D4）。

### 3.4 F20–F23 的含义（**本轮最重要的结论**）

批次 3 的扫描已经做完（`07` 号文档）。**结论是「当前策略族未检出优势」，而不是「找到了 143 只可荐标的」**：

- 门禁确实**能被满足**（143/10,572），所以链路是活的、不是设计死锁——这一半是好消息；
- 但**安慰剂对照（把逐日收益随机重排）产出 279 个 candidate，是真实数据的 1.95 倍**；
  跑赢买入持有基准的只有 **36** 个，而安慰剂有 **110** 个。
  **真实序列结构对本策略的顺序敏感性是负的 → 未检出择时优势。**
- 因此 D16/D17/D18/D19：**C2 的目标准从"找能荐的股票"改为"先把评价口径做实"；
  `trend_20_60_v1` 判定未检出优势、不得作为信号源；`reversal_5d_v1` 退役或重新预注册；
  安慰剂对照固化为常备机制。** 详见 `07` 号文档 §5。
- **下一步顺序已改变**（`07` §6）：批次 1（治理表）→ **把本次扫描登记入册** → 双轨结算 →
  再做（重定义后的）C2。原"批次 3"标记为已完成。

## 5. 危险操作警告（历史的教训，别重犯）

1. **不要重写 git 历史。** 已经重写两次（清除凭据 DB 与全部 `.test-tmp`）。原因：重写**无法**
   清除服务端（GitHub）的不可达对象——那是服务端行为，客户端改不了；而每重写一次都会改变
   **全部**提交 SHA 并要求再次 force-push，风险远大于收益。
2. **不要再做 `git add -A` 而不先 dry-run。** `.gitignore` 已加固，但 `data/` 下曾有一份 884 MB
   的行情数据被误暂存过。**每次提交前先 `git add -A --dry-run` 看清单。**
3. **不要删除标签 `archive/pre-v2-2026-09-02`。**
4. **不要删除或提交 `data/db/finsight.db`、不要删除 `data/market/` 下任何数据。**
5. **不要为了通过测试而放宽门禁**，也不要把测试改绿当成修好了——真实回归要改生产代码
   （F16 就是这么处理的）。
6. **提交时加 `-c gc.auto=0`**：仓库曾因残留临时 pack 触发自动 gc 而超时。
7. **不要接受用户递来的凭据文件**（见 §4 的「凭据边界」硬规则）。用户主动提供时，
   标准回复是：说明不接受的原因 + 给出他自己在自己终端里完成授权的具体步骤。
   推送凭据这个问题**只有用户能解决，而且不需要经过 agent**。
