# 实盘验证操作手册

> **这份手册是给你照着做的。**不需要理解任何算法细节，只需要在每个交易日的固定时间，
> 按顺序点完下面这些步骤。所有测试数据由系统自动落盘，你不需要手工记录任何数字。
>
> 固定工作时段：**交易日 15:45–18:30**（收盘后数据才闭合）。
> 错过某天不补造历史记录，下一个交易日继续。

---

## 0. 开始之前必须知道的四件事

1. **现在的系统还不会给出「买入」。** C1 落地前，顾问对任何股票都会输出「等待」或
   「证据不足」。这是**预期行为，不是故障**——因为它缺少通过历史门禁的策略实验记录。
   这段时间你跑出来的等待/拒答本身就是数据（它证明链路是通的、且门禁没有被放宽）。
2. **每个交易日最多 3 只候选。** 这是刻意的小样本设计，不是限制。不够 2 只就不凑数。
3. **不要为了让系统说「买入」而反复改写提问或追问。** 这会让整批数据作废。
   系统输出等待或拒答，必须原样保留。
4. **本系统不会下单、不会连接券商、不会发通知。** 真实盈亏只以券商成交记录为准。

## 1. 一次性准备（首次约 30 分钟）

| 步 | 位置 | 动作 | 通过标准 |
|---|---|---|---|
| 1.1 | 双击项目根目录 `启动FinSight.bat` | 等待黑窗口显示前后端就绪，浏览器自动打开 `http://127.0.0.1:5173` | 页面能打开 |
| 1.2 | 左侧「模型与 API 配置」 | 确认至少 1 个模型处于**启用**状态 | 有启用标记 |
| 1.3 | 同上页 | 依次点「模型聊天测试」和「工具调用测试」 | **两项都出现成功**才算通过 |
| 1.4 | 同上页 | 确认同花顺数据能力测试通过（能返回最新完整交易日日 K） | 测试成功 |
| 1.5 | 同上页 | 确认付费搜索（博查）可用 | 测试成功 |
| 1.6 | 备份 `.env` | 把项目根目录的 `.env` 私下复制一份到安全位置 | **丢了它，已存的 API Key 密文就永远解不开** |

> 1.3 两项必须都成功。只成功一项时，当天不要进入第 2 步。

---

## 2. 每日流程（10–60 分钟，按顺序做）

### 第 1 步 · 数据刷新（10–15 分钟）

| 顺序 | 位置 | 动作 |
|---|---|---|
| ① | 左侧「新闻订阅」 | 逐个 RSS 源点右侧「刷新」，或点页面下方「全部刷新」；再点「拉取官方资讯」 |
| ② | 左侧「市场复盘」 | 确认日期是**最新完整交易日** → 点「显式刷新盘后观察」 |
| ③ | 左侧「全市场观察」 | 点「显式同步近 10 日」→ 弹窗确认 → 选最新完整交易日 → 点「生成当日全市场看板」 |

**检查**：三个页面都要显示真实刷新时间和数据日期。任一失败 → 当天到此为止，不进入第 2 步。

### 第 2 步 · 生成候选（5 分钟）

按固定规则（**每次都用同一套规则，不得临时更换**）：

1. 从「市场复盘」取**热度前 5**。
2. 从「全市场观察」取**成交额前 10**。
3. 合并去重，排除：ST、停牌、次日无法正常买入的连续涨停股、身份无法确认的证券。
4. 同时出现在两张榜单的优先，其余按成交额排序。
5. **每天最多保留 3 只；不足 2 只不凑数。**

然后把每只标的在「研究概览 → 数据预览」里搜索并点「**确认**」——
**没有确认过的标的，后面所有页面都不会给数据。**

### 第 3 步 · 逐只发起顾问研究（每只 10–20 分钟）

对**每一只**候选，单独操作一遍：

1. 左侧点「**AI 聊天**」→ 点「**新建会话**」（**一只股票一个会话，绝不混用**）。
2. 模式选「**深度**」（deep）。
3. 勾选「**本次允许联网搜索**」。
4. 把下面这段提示词里的日期、名称、完整代码替换后，**原样**提交：

```text
今天是 YYYY-MM-DD，A 股已经收盘。请对【股票名称，完整代码】做一次未来 5 个交易日的建仓决策研究。

我的目标：判断下一个交易日是否值得建立试探仓；只评估这一只股票，不扩大到其他标的。

资金约束：这只股票最多占总资金 10%；单笔可接受最大亏损 2%；不融资、不追涨停、不在证据不足时买入。

请实际使用本轮能够取得的同花顺最新完整日 K、历史日 K、F10 财务与估值、资金/异动数据、本地 RSS、私有知识库以及联网搜索摘要。搜索和 RSS 只能作为线索，关键事实必须交叉验证。

必须给出：明确方向、5 个交易日上涨/震荡/下跌概率、建议档位、关键证据、最强反方证据、什么情况下判断作废、可量化跟踪哨，以及是否满足“明日可试探买入”。如果候选策略或证据门禁不满足，请明确等待或拒答，不要为了迎合我而改成买入。
```

5. 等待完成。页面会实时显示阶段，完成后可点「查看本次分析过程」。
6. **不要追问、不要重试、不要换说法再问一遍。**

### 第 4 步 · 核对入库（5 分钟）

在「AI 聊天」页的页签里：

| 页签 | 看什么 |
|---|---|
| **执行建议台账** | 核对证券代码、基准日期、方向、档位、持有期、建议正文 |
| **研究预测封存** | 确认非拒答建议生成了 H5 预测；记录**建议 ID** |

**判定「可执行买入信号」必须同时满足 4 条**（任一不满足，当天就不买）：

1. 方向为加仓或买入（不是等待、减仓、拒答）；
2. 档位至少为 `trial_buy_signal`；
3. 没有未解决的关键证据冲突；
4. 给出了明确的失效条件、风险限制和可跟踪观察哨。

> C1 落地前，第 2 条几乎必然不满足 → 当天不买，这是正确结果。

### 第 5 步 · 落盘（1 分钟）

点「**导出今日测试数据**」（C1 落地后提供）。

系统自动写入 `data/exports/test-runs/<今日日期>/`：

| 文件 | 用途 |
|---|---|
| `daily.md` | 当日候选、每只的建议卡、证据编号、档位与理由（给你看） |
| `daily.jsonl` | 同上，逐条一行 JSON（给统计脚本用） |
| `batch.json` | 批次号、参数哈希、数据快照哈希、模型配置 ID（审计用） |

**检查**：确认这三个文件都生成且非空。若按钮不存在，说明 C1 尚未落地，
此时数据仍已自动写入 `data/db/finsight.db`，不会丢失。

## 3. 每周流程（20–30 分钟）

在每周最后一个交易日，先做完第 2 节的第 1 步（刷新数据），然后：

1. 进入「AI 聊天」→ 点「**结算已到期记录（最多 50 条）**」。
2. 结算所有走完 5 个交易日的建议与预测。
3. 核对结算基准价、到期价、实际方向、收益、校验信息。
4. **数据不足的记录保持未结算，不手工猜测结果。**
5. 点「导出今日测试数据」（或本周汇总导出）完成落盘。

真实成交（如果你实际买了）**记录在券商成交单或你自己的只读台账里**，需要包含：
FinSight 建议 ID、完整代码、委托与成交时间、成交价与数量、佣金印花税等费用、
平仓时间与原因、未执行时的原因。系统不保存持仓。

---

## 4. 什么时候判定成功或失败

这些门槛**在开始前就已固定**，中途不得修改：

| 检查点 | 判据 | 结论 |
|---|---|---|
| 第 10 个交易日 | 一条 `trial_buy_signal` 都没有，或关键工具频繁失败 | **当前版本不具备实际荐股可用性**，停止实盘尝试 |
| ≥30 条已结算预测 | 方向命中率的 95% 置信区间包含 50% | **无方向优势**（只展示结果，不下稳定有效结论） |
| ≥60 条已结算且满 12 周 | 未优于简单基准，或真实净收益为负 | **正式停用** |
| 任意时点 | AI 裁决轨显著劣于策略轨 | 移除 LLM 的方向权限，降级为纯解释 |

**不要**因为结果不好而延长观察期、降低标准或改写规则。判定失败本身是合格的科研结论。

---

## 5. 禁止事项

1. 不使用盘中波动临时替换固定候选规则。
2. 不删除等待、拒答或亏损的建议。
3. 不对同一标的重复生成，直到出现想要的答案。
4. 不把候选列表本身当作系统已经给出的买入建议。
5. 不直接编辑 `data/db/finsight.db` 修补结果。
6. 不运行自动轮询、自动荐股、自动补跑或历史回填任务。
7. 不把未成交委托计作真实交易。
8. 不把多个建议合并为一笔无法追溯的成交。

---

## 6. 每天结束时的三行确认

```
[ ] 三个数据页面都显示了今天/最新交易日的真实时间
[ ] 每只候选都有独立会话，且能查到建议 ID
[ ] data/exports/test-runs/<今天>/ 下有 daily.md、daily.jsonl、batch.json
```

三行都打勾，这一天的验证就完成了。**记录本身就是数据，你不需要额外写任何东西。**

## 7. 出问题时怎么办

| 现象 | 处理 |
|---|---|
| 提示「请先在数据预览中确认标的」 | 去「研究概览 → 数据预览」搜索并点「确认」 |
| 提示「未配置模型 / 模型未激活」 | 去「模型与 API 配置」启用并测试 |
| 提示「无权限 / 额度限制」 | 该数据能力的 Key 或账号权限问题，去设置页重新测试 |
| 表格/KPI 显示 `--` | 本地缺该项证据，点对应「刷新」补数据；**不要手工填 0** |
| 报告拒绝删除 | 它仍被投资理由引用，先解除引用 |
| 进程重启后任务显示「中断」 | 进行中的任务被标记中断，**不会自动重放付费请求**，需要时手动重发 |
| 页面数据看起来是旧的 | 页面显示的是上次刷新的快照，点刷新按钮 |
| 顾问一直输出「等待 / 证据不足」 | **C1 落地前属预期**。若 C1 已完成仍持续如此，记录到日志并检查策略实验是否产出 |

## 8. 这份手册之外你要做的事

只有一件：**真实买卖由你在券商侧完成与记录**，系统不参与。

其余全部（取数、取证、生成建议、登记台账、封存预测、结算、落盘）都由系统完成。
