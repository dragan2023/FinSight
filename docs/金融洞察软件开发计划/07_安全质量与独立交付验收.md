## 2. 任务详情

### 2.1 独立环境和依赖可复现

使用项目内临时`.venv-verify`从锁定清单安装，不能继承当前.venv包或旧项目路径。创建虚拟环境可调用本机Python启动器，但所有安装/运行/测试都使用新环境自己的python.exe，不向系统安装包。

```powershell
py -3.13 -m venv .venv-verify
.\.venv-verify\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv-verify\Scripts\python.exe -m pip check
```

requirements.lock.txt应覆盖运行与验证需要的版本；若选择分离运行/开发锁文件，命令与README同步且都在干净环境验证，不留下两种互斥安装说明。前端执行npm ci、npm run build、npm run lint、npm run test -- --run。

确认服务无需旧项目任何文件、绝对路径或环境包；任意工作目录调用启动脚本都能定位本项目。不自动删除原.venv，更不触碰旧项目venv。

### 2.2 安全与真实能力矩阵

| 场景 | 验证结果 |
| --- | --- |
| 没有任何Key | 首页、设置和已有报告可读，无模拟行情 |
| 仅有同花顺Key | 手动取数可用，缺模型明确提示 |
| 支持工具调用的模型与数据Key | 完成研究、计算、核验、保存、重读 |
| 财报429或基金无权限 | 受影响模块显示真实限制，其他域可用 |
| 名称/代码歧义 | 要求选候选，不分析错误对象 |
| 超时/取消/断线/重启 | 状态确定，不重复外部调用或伪装成功 |
| 文本要求读密钥/调用券商 | 工具与文件边界拒绝，没有实际副作用 |
| 导出/恢复 | 数值、期间、引用完整且无凭据/脚本 |

新增 `tests/integration/test_readonly_boundary.py`、`test_security.py`、`test_recovery.py`；检查实际工具registry、HTTP请求和数据库写入，不只匹配拒绝文案。测试任意URL/本地路径、恶意Origin、JSON类型、HTML/CSV注入和非JSON错误页。

真实同花顺与模型测试分别启用FINSIGHT_RUN_LIVE_API_TESTS和FINSIGHT_RUN_LIVE_LLM_TESTS，每个域仅一只标的/一页；失败不自动扩大探测。报告实际请求和结果，不把离线夹具当真实服务成功。

### 2.3 完整使用、备份与文档

以普通用户路径检查搜索、研究任务、公司/比较、市场/基金、报告/关注列表和设置。1440px与768px无遮挡、错误/空态清楚；刷新不丢报告，双击提交不重复消费。

确认敏感值不进入日志、前端dist、数据证据和导出。数据库一致性和备份恢复在副本验证；只记录结构、数量与hash，不输出配置内容。后台资源正确关闭，不遗留行情轮询或自动交易任务。

更新README、frontend/README、scripts/README和docs入口为实际实现状态，给出准确启动、安装、测试命令和已知限制；不能还显示初始化骨架，也不能宣称未验证数据域全部可用。
