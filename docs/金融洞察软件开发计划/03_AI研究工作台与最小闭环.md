## 2. 任务详情

### 2.1 建立真正的只读工具循环

新增 `agent/graph.py`、`tools.py`、`prompts.py`、`research/models.py`、`service.py`、`repository.py` 和 `analysis/price_metrics.py`。复用 LangGraph StateGraph 与已有模型客户端，不创建多个人格互相投票、不自建通用 Agent 框架。

```text
消歧 → 规划 → 选择并调用工具 → 计算/整理 → 核验证据 → 保存
                  ↑            |
                  └─预算内补数─┘
```

最小工具为 resolve_instrument、read_snapshot、read_daily_bars、read_valuations、calculate_price_metrics。Pydantic 严格校验参数，拒绝额外字段；工具列表在后端固定注册，模型不能修改。模型可以按问题选择必要数据，并在预算内补充请求，而不是对每个问题固定拉同一批数据。

初始上限：8轮工具循环、12次远端请求、120秒总时间；模型token预算来自活动配置。重试计入次数，等待计入总时限；达到限制应给出partial或明确错误。没有Shell、任意SQL/Python、文件写入、券商或订单工具。

### 2.2 确定性计算与报告核验

price_metrics 首版实现同复权日线的区间涨跌幅和最大回撤：日期排序、去重、缺失校验，区间涨跌为末值/首值−1，回撤相对累计最高值计算。展示实际样本期、复权、当日未完成和数据缺口；这些是价格描述，不是策略收益或回测。

ResearchRequest 定义 question、instruments、date_range、analysis_kind、client_request_id；不接受用户自定义 system prompt、URL或工具清单。ResearchReport 定义 id、task_id、version、question、instruments、summary、claims、metrics、evidence_ids、limitations、created_at、model_label、data_cutoff。

每个claim标注fact/derived/inference；事实和计算结论关联有效证据，推断也要列明依据与局限。每个metric包含输入证据、字段、公式版本、单位和期间。模型输出结构化报告后核对引用存在、标的/日期匹配、关键数值来源与计算一致。

发现不一致最多有界修复一次；仍失败则报告partial/failed，不让模型用“已核验”文字自我认证。模型隐藏推理链不进入UI或数据库；只展示工具步骤、公开参数摘要、来源和可审计结论。

### 2.3 可持久化任务与接口

在 finsight.db 增加 research_tasks、research_events、reports、report_evidence 表，引用02的evidence表；使用 storage.py 的单一迁移入口。单进程 asyncio 管理正在运行的任务句柄，semaphore 限制并发；DB记录结果与事件，不引入分布式队列。

新增 `api/research.py`、`api/reports.py`：

| 端点 | 语义 |
| --- | --- |
| POST /api/research/tasks | 202 + task_id；同client_request_id与相同请求幂等，相同ID不同载荷返回冲突 |
| GET /api/research/tasks/{id} | 阶段、状态、可用数据、错误分类、report_id |
| GET /api/research/tasks/{id}/events | 仅研究进度SSE，事件ID持久化，重连不重跑研究 |
| POST /api/research/tasks/{id}/cancel | 幂等取消，不继续开始新工具调用 |
| GET /api/reports/{id} | 持久化报告及来源引用 |

任务状态为queued/running/completed/partial/failed/cancelled/interrupted；取消后即便已发请求完成，也不能覆盖成completed。进程重启把遗留running/queued标记interrupted，不自动重放可能收费的API或模型请求。

失败处理区分缺Key、模型不支持工具调用、429、参数错误、合法空数据、证据不足。无模型时保留手动数据卡和旧报告读取，不以模板报告伪称AI成功。

### 2.4 研究工作台与最小验收

新增 `frontend/src/pages/Research/index.tsx`、`pages/Reports/ReportDetail.tsx`、`api/research.ts`、`api/reports.ts`、`types/research.ts`、`hooks/useResearchTask.ts`、`components/Research/Progress.tsx`、`EvidencePanel.tsx`、`ReportView.tsx`。本组省略的前缀均为frontend/src，EvidencePanel和ReportView与Progress同目录。路由为首页工作台、`/research/:id`与`/reports/:id`。

工作台包含问题、已选标的、时间范围、数据卡和最近任务。运行中显示工具进度/来源/取消；完成后显示报告和限制。每个关键数字可钻取来源。SSE失败可轮询状态，不能重新POST创建任务。

展示Markdown使用成熟解析库并禁用原始HTML或严格消毒，不执行供应商文本。需要图表时增加一套ECharts及React封装，直接依赖显式写入package.json，不依赖偶然存在的包。适配1440px和768px布局，表格可横向滚动。

最小真实问题：“解释这只股票最近一段时间的价格表现，列出当前估值和分析限制。”至少实际取数、进行一种确定性计算、生成引用报告、保存并刷新重读。财务仍受限也能完成这个闭环，但不得产生营收/利润事实。

## 3. 禁止事项与兼容性

供应商文本和用户附件属于不可信数据，不能成为系统指令。不为实现工具调用开放任意代码执行；不读取.env/数据库密钥；不生成下单、仓位或策略分数。拒绝交易行为须由工具能力与后端边界保证，不只靠Prompt。

## 4. 验收标准

- [ ] 用户问题能引发必要的工具选择、真实数据调用和确定性计算。
- [ ] 每条已验证事实/计算有可定位证据；不支持结论明确列为局限。
- [ ] 报告跨刷新/重启可读；重连和重复提交不重复消费。
- [ ] 取消、超时、429、无模型、不兼容模型均有明确行为。
- [ ] 新增 `tests/unit/agent/test_tools.py`、`test_graph.py`、`tests/unit/analysis/test_price_metrics.py`、`tests/integration/test_research_flow.py`并离线通过。
- [ ] 注入文本要求读取密钥/执行交易时，实际工具调用和持久化均无越权。
- [ ] 新项目进行一次受控真实API+模型验收，requires_api/requires_llm及各自开关同时开启。

到此形成MVP，可开始实际使用；04–06属于在此基础上的扩展，不是MVP的前置条件。
