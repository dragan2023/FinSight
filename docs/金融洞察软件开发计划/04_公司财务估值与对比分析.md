## 2. 任务详情

### 2.1 财报与指标接入

扩展market_data的三个文件，新增 `backend/app/analysis/financial_metrics.py`、`metric_definitions.py`、`comparison.py`。对接income-statements、balance-sheets、cash-flow-statements与indicators；显式传period，最近N期与start/end互斥。首版默认4–8期，不无限请求历史。

保留period_end_ms与report_date_ms，前者为期间/期末，后者为报告日期；不会因为最新日期相同就判定报表期间一致。indicators的abilities是数组，value可为字符串/null；指标字典只映射经核实的index_id、单位、标签和解析规则。

quarterly不自动视为单季值。累计/单季语义未确认前不做差分、不将季度值直接求和TTM；未知指标保留原值并标为未映射。财务三表的口径证据独立验证，不让LLM猜测单位。

### 2.2 可复算指标和比较规则

| 指标 | 计算与约束 |
| --- | --- |
| 营收同比 | 相同期间/口径，(本期/上年同期−1)×100；基期≤0/缺失时不输出百分比 |
| 归母净利变化 | 同期绝对额差；正基数可补同比，扭亏用金额说明 |
| 归母净利占营收 | parent_holder_net_profit/operating_income×100；标签明确归母口径 |
| 资产负债率 | 同一期末total_debt/assets_total×100；资产≤0不可算 |
| 经营现金流/净利润 | 同期间act_cash_flow_net/net_profit；净利润≤0不输出健康评级 |
| 研发投入比 | research_and_development_expenses/operating_income×100；未披露不补零 |

公式以确定性代码执行，保存输入证据和公式版本。分母为零、负值、缺失与期间错位有独立原因；不用旧项目的Money/Percentage或因子评分。

估值只展示当前PE_TTM、PE_MRQ、PB_MRQ、PS_TTM、PCF_TTM；负值/null保留，不把负PE排序成最便宜。不提供历史PE分位、估值曲线、PEG或目标价，因为当前数据不足以支撑。

对比限定用户选定的2–5家公司；默认选择共同可比期间，允许查看各自最新期但明确不可直接横比。单指标排序说明口径，不合成荐股分数；不扩展到全市场因子选股。

### 2.3 公司页、比较页与真实验证

新增 `backend/app/api/company.py`、`comparison.py`；前端新增 `frontend/src/pages/Company/index.tsx`、`pages/Compare/index.tsx`、`api/company.ts`、`api/comparison.ts`。路由为`/company/:thscode`、`/compare`。

接口：GET `/api/company/{thscode}/financials?period=&limit=`、GET `/api/company/{thscode}/metrics?report=`、POST `/api/comparisons`。返回统一的证据/来源契约，财报部分失败不清空已经成功的价格估值。

公司页呈现身份、价格、财务、估值、风险解释与证据；比较页始终显示期间/单位/缺失状态。用户可把当前对比数据加入研究问题，复用已有证据而非再次请求所有数据。

此前利润表两次返回429：本阶段按单股annual limit=1低频重新验证，仍受限则财务页显示受限，不用旧数据源或模型常识填补。三表与指标要分别验收；财务权限问题不阻止05/06继续开发。

## 3. 禁止事项与兼容性

不输出买卖建议工具、仓位或策略收益；不把时点值当流量求和TTM。不把不同行业/期间的数据强行统一为准确排名。API失败不能变成“公司没有收入”，披露缺失不能变成零。

- [ ] 年报、亏损、零分母、缺失、季度口径不明、报表更正有测试。
