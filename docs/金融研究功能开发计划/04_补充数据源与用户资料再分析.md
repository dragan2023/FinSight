# 04 — 补充数据源与用户资料再分析

## 1. 摘要与前置阅读

优先级 P0；预计 4–5 批；直接依赖 01–03；目标：由用户决定如何补足缺口，接入已经调研的搜索/结构化补充源和本地资料，保留出处、许可、冲突及再分析版本。

前置阅读：`调研资料/补充数据源调研与选型.md`；01 的 `api_config/` 与设置页；02 的 `market_data/normalization.py`、`field_dictionary.py`、`research/evidence_store.py`；03 的 `research/supplements.py`、`service.py`、`agent/tools.py`、`output_validation.py`；现有 `backend/app/security.py`、`main.py`、`settings.py`、`requirements.txt`。新增适配器仅复用 httpx，不因为接入多家服务再增加一批官方/非官方 SDK。

## 2. 任务详情

### 2.1 接入取舍与可见配置

本阶段按以下结论执行，不以“以后调研”占位：

| 来源 | 本次决定 | 能补什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 博查 Web Search | 接入，供用户选作中文联网搜索 | 公告、解释性材料、原文线索 | 搜索摘要不能充当精确财务数据 |
| Tavily Search / Extract | 接入，两种能力独立授权 | 检索与按 URL 提取正文 | 可提取不代表有长期存储/再分发权 |
| Tushare Pro | 接入可选个人研究适配器，默认关闭 | 财务、披露、审计、主营构成、历史估值等按账号权限补充 | 用户 Token 不自动赋予产品商用权 |
| 官方公开原文、本地附件 | 接入受限读取/上传 | 公司公告原文和用户自己拥有的材料 | 不是全网爬虫，也不保证 PDF 表格无误 |
| Brave、AKShare、BaoStock、第三方聚合接口 | 首版不接入 | 调研中保留候选说明 | 不宣称免费、无限、授权无风险 |

更新 `api_config/catalog.py` 和 `frontend/src/pages/Settings/ApiProviders.tsx` 的真实实现状态；所有已接入 API 都能看到自己的 Key/Token、测试、启停、用途、权限/额度提示、数据流向和官方申请链接。Tavily 一份 Key 下的 Search/Extract 单独测试；没有自动开启模型内置搜索、付费 OCR 或隐藏代理 API。

Tushare 个人使用条款不能作为商业发行许可。当前个人版本只有用户明确了解对应许可后启用；未来商业包没有适用书面授权时不提供该适配器，其他功能继续工作。该边界也适用于同花顺等数据再分发和送入外部 LLM 的处理权限，BYOK 不替代许可审查。

### 2.2 搜索与原文的薄适配器

新增 `backend/app/web_research/models.py`、`bocha.py`、`tavily.py`、`service.py`、`public_reader.py`、`url_safety.py`。将结果归一为 title、url、publisher、published_at、retrieved_at、snippet/body、source、storage_policy、查询范围及证据 ID；缺失发布时间为 unknown，不从抓取时间猜。

博查使用 `https://api.bocha.cn/v1/web-search`、Bearer Key，按官方契约发送 query、freshness、summary、count。仅发送已核验参数；未确认服务端支持的域名筛选在本地做，并注明并不保证搜索召回完整。

Tavily 使用 `https://api.tavily.com/search` 和 `/extract`、用户自己的认证。Search 默认 `include_answer=false`、`auto_parameters=false`、basic 深度，固定本次选定的条数/时间/域名约束；不得让服务端自动升级深度增加费用。Extract 单独计预算，逐 URL 记录失败；全文抓取失败不使整次研究失败，不把摘要标为全文。

查询优先围绕用户选定标的、公开名称/代码、时期和已知缺口生成；优先官方交易所、巨潮、公司投资者关系等一手材料，媒体用作线索和补充。必须校验名称/代码、公告主体、报告期及原文时间，转载去重保留原始发布者；搜索排名、摘要相关性不等于金融可信度。搜索提供的现成 AI 答案不作为独立事实来源。

### 2.3 公开 URL 读取与外发授权

公开原文读取只允许 HTTPS、443、预设的官方域名与经用户明确加入的发行人官网，不允许任意网址自动爬取。默认目录以 `www.cninfo.com.cn`、`static.cninfo.com.cn`、`www.sse.com.cn`、`www.szse.cn` 为起点，新增实际公告域名单独核对；不开放整个顶级域名通配，不绕过登录、验证码、付费墙或站点限制。

URL 校验拒绝 userinfo、非常规端口、IP 字面量、localhost、私有/链路本地/保留/云元数据地址及混淆编码；解析所有 A/AAAA 记录检查可公开路由。连接必须绑定已经验证的解析结果，同时保留原 hostname 的 TLS/SNI 验证，不能“先查一次 DNS 再让普通客户端重新解析”。该逻辑限制在 `url_safety.py`/公开读取专用 transport，不改模型固定官方客户端。

默认不跟随重定向；用户可选择读取的新目标仍须重新通过全部规则，原始凭据/会话/Cookie 不转发。只接受 HTML/纯文本/PDF，流式限制下载 25 MiB、解压后 50 MiB、总时间 60 秒；页面脚本不执行，不加载图片/iframe/字体和子资源。无法安全读取时提供 Tavily Extract 或手动上传入口，不能用关闭 TLS/SSRF 防护解决。安全设计依据 [OWASP SSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

用户在任务启动时明确允许的公开检索可在预算内执行；上传私有资料的内容、完整研究笔记不自动加入搜索 query，不自动上传搜索平台。搜索、外部正文提取、将片段送至所选 LLM 是三个不同数据流向，页面一次性清楚展示本任务选择，超出原选择时由用户主动启用。

### 2.4 Tushare 结构化补充与冲突

新增 `backend/app/market_data/tushare_client.py`；扩展 `identity.py`、`field_dictionary.py` 与 `service.py`。使用 `https://api.tushare.pro`，Token 放官方请求体，不允许降级到明文 HTTP。公开 HTTPS 空请求已确认能得到应用响应，但本次没有付费 Token 的真实数据验收；联调仍须验证实际账号、接口与额度。

| Tushare API | 补充目标与要求 |
| --- | --- |
| stock_basic | 股票身份/行业等元信息，核对代码映射，不直接拼接 thscode |
| daily_basic | PE/PB 等历史序列；只有完整有效窗口才计算该窗口历史分位 |
| income、balancesheet、cashflow | 同一标的/报告期的三表缺口，保留报表类型与修订信息 |
| fina_indicator | 可比财务指标；账号可能需积分权限 |
| fina_audit | 审计意见，仅对实际返回期间展示 |
| fina_mainbz | 主营构成，仅对实际权限和披露覆盖展示 |
| disclosure_date | 披露计划与实际日期区分，不将计划当实际已披露 |

只请求用户选定标的/期间的必要 fields，校验 fields/items 的字段对齐、行长度与错误码。权限门槛和限流由官方文档与真实错误共同识别，不能把某个积分数字当永久承诺；未授权接口变为具体 DataGap，不阻止其他来源。

相同财务指标跨源比较前校验 entity、period、currency、unit、合并/母公司、累计/单季、披露版本和定义。完全可比且主源缺失时，用户已授权的补充源可填入规范化字段，同时保存替代来源；有冲突时并列显示，禁止平均、择大或静默覆盖。用户选择一个来源仅影响本次新报告，不修改历史证据；两个来源口径不同就并列解释，不强行比较。

历史估值分位注明指标、窗口、有效交易日数、负值处理、缺失比例和公式。历史窗口短时只能叫该实际窗口分位；不能用一年数据称十年分位。首版不补海外/宏观/实时新闻数据库，因为本轮功能没有形成必须接入这些新 API 的明确闭环。

### 2.5 本地资料解析与候选证据

新增 `backend/app/research/attachments.py`、`attachment_parsers.py`、`attachment_worker.py`；新增 `frontend/src/components/SupplementPanel/index.tsx`、`components/SourceConflict/index.tsx`。支持 TXT、Markdown、CSV、XLSX、文本型 PDF，以及用户主动选用已配置视觉模型时的 PNG/JPEG 图片。拒绝可执行文件、宏工作簿、HTML 上传和归档包；不得根据扩展名直接信任内容。

复用 stdlib CSV/文本；新增成熟依赖 pypdf、openpyxl、defusedxml 与上传所需 python-multipart，实施时核验兼容版本并锁定。openpyxl 使用只读模式、不执行公式/宏/外部链接；有缓存值也说明其并未重新计算。pypdf 只能提取文本层，表格和扫描页需要确认，不能承诺 OCR；参考 [pypdf 提取限制](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)、[openpyxl 文档与安全说明](https://openpyxl.readthedocs.io/en/stable/)。

首版默认单文件 25 MiB、一次最多 5 个/合计 100 MiB、PDF 最多 200 页、每工作簿最多 100000 个实际处理单元格/每表 10000 行；这是可见的产品上限，不因读取失败让整个任务报错。ZIP 解压后累计 50 MiB、单条压缩倍率上限 100，拒绝 XML 外部实体及爆炸展开。原始文件随机命名存 `data/attachments/`，原文件名仅为显示字段，绝不拼接服务器路径。

解析在独立短生命周期子进程中进行，单文件 60 秒；默认 512 MiB 内存硬限制。在 Windows 使用成熟 pywin32 的 Job Object 约束内存与子进程树，并加到带 Windows 环境标记的依赖；先约束后开始解析，关闭/超限即清理子进程。其用途仅是隔离不可信文档解析，不引入常驻队列或第二服务。不支持相应限制的平台不得开放文件解析入口而声称同等安全。依赖只装项目 `.venv`，不运行面向全局安装的 pywin32_postinstall；参考 [pywin32](https://github.com/mhammond/pywin32)、[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

`security.py` 仅对附件上传路由允许受限 multipart，保留 Host/Origin/会话验证和实际流字节计数；不要把现有全局 JSON/32 KiB 限制全部关闭。文字补充仍用单独小 JSON schema 和长度限制。上传先本地解析，不调用外部模型；保存并查看资料不等于同意外发。

解析子进程只接收受控文件 ID/路径和解析选项，清理继承环境中的 API/根密钥，不初始化应用配置、不访问网络。Job Object 是资源约束，不是完备恶意代码沙箱；持续更新解析库，未来公网不可信上传还须满足 08 的更强隔离门槛。

解析结果记录页码/表名/行列、原文片段、拟映射指标和解析警告。PDF/视觉识别的表格金额只作为候选，用户确认标的、期间、单位和字段映射后才进入确定性计算；“用户确认”仍标 user_provided，不冒充官方接口数据。扫描 PDF 给出“无文本层”，可上传少量页面截图，明确选择当前已配置且支持视觉的模型分析；不接入隐藏 OCR 服务、不要求为缺图更换模型。

用户可选具体页/行/片段送至 LLM，默认最小必要内容；图片默认一次最多 5 张，并同时受模型实际输入能力限制。模型解析图片后仍适用 03 的 JSON/证据校验。单个文件损坏、受密码保护、乱码、超限或字段不明，保留其他成功资料并给出补救入口。

### 2.6 许可保留策略、补充接口与再分析

扩展 evidence 的 `storage_policy=full|excerpt|reference_only|ephemeral` 及许可依据；长期保存、向模型外发、导出分享分别判断。没有明确许可不能默认永久存提取全文，也不能用“摘录”名义规避禁止存储。受限原文仅在授权任务内存中使用，结束释放；记录允许保存的引用与缺口，报告说明部分出处内容不可离线复核。

新增 `backend/app/api/supplements.py`：POST `/api/supplements/files` 上传，GET `/api/supplements/{id}` 预览，PUT `/api/supplements/{id}/mapping` 确认候选字段，DELETE `/api/supplements/{id}` 删除未引用资料/按保留规则处理已引用资料；POST `/api/research/tasks/{id}/source-preview` 只预览本地拟定的数据流与预算，不自动调用来源。真正再分析沿用 03 `/reports/{id}/reanalyze`。

UI 在缺口旁提供“配置数据源”“上传/粘贴”“选择已有资料”“保留缺口”；补充后列出哪些缺口已具备候选证据、哪些仍未知，让用户勾选本次资料再启动。冲突的选择和假设说明写入新版本，原版不改。对所有新来源都显示当前已启用配置；禁用/删除后不得借用另一份配置偷偷继续请求。

## 3. 禁止事项与兼容性

不把搜索摘要当财报、不将用户修改覆盖原件、不默认爬取全站、不绕过数据许可。不为保证分析“看起来完整”填入推测数字。所有新 Key 入口都必须位于现有设置页，不能藏在 `.env`、代码或仅管理员可访问的脚本。03 无联网补充也必须继续可用。
