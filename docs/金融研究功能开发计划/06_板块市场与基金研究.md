# 06 — 板块市场与基金研究

## 1. 摘要与前置阅读

优先级 P1；预计 4–5 批；直接依赖 01–04；目标：实现板块相对表现、披露持仓重叠、基金质量和与用户关注对象相关的市场复盘。可在 04 后独立执行，不依赖 05 的业务模块。

前置阅读：02 的 `market_data/ths_client.py`、`identity.py`、`field_dictionary.py`、`analysis/price_metrics.py`；03 的研究任务/报告/缺口；04 的联网证据和授权；现有 App、Layout、storage、设置页。同花顺依据为 [指数契约](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/endpoints-index.md)、[基金契约](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/endpoints-fund.md)、[特色数据契约](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/endpoints-special-data.md) 及本计划能力调研。

## 2. 任务详情

### 2.1 扩展数据能力且保持来源可见

新增 `backend/app/market_data/index_data.py`、`fund_data.py`、`market_events.py`，复用同一个 ThsClient/凭据、DataResult 与 evidence_store，不创建基金专属密钥或数据库。扩展设置页中同花顺指数、基金资料、净值、持仓、特色数据能力测试；只在用户点击测试/研究时取数。

| 模块 | 直接调用的能力 |
| --- | --- |
| 板块 | a-share-index/catalog/ths-index-list、constituents/ths-stock-list、prices/snapshot、prices/historical |
| 基金基础与质量 | fund/profile/detail、performance/nav、returns、drawdowns，必要时 managers/experience、performance |
| 披露持仓 | fund/portfolio/holdings、stock-report-dates、stock-history、industry-allocation、asset-allocation |
| 指数基金观察 | 基金净值、已确认跟踪指数、适用时 performance/indicators-historical；场内行情只按相应支持范围 |
| 市场事件 | limit-up/down/break-pool、热榜、dragon-tiger-list、当日 anomaly-analysis-stock 等，默认只查询相关对象 |

`fund_type` 由元信息资产类型确认，不能凭代码后缀猜；OTC/场内/REITs 不能用同一 schema 假定全部字段适用。基金诊断、经理雷达等供应商结论如后续展示必须标注供应商评价，本阶段不将其作为自研评分的事实输入。

### 2.2 板块相对表现与参与广度

新增 `backend/app/analysis/relative_performance.py`、`research/sectors.py`。用户选择股票及 1–3 个指数/板块，观察共同日期窗口的归一化走势、区间变化、最大回撤和相对差值。共同起点归一为 100，公式为 `P_t / P_start × 100`；区间收益差明确为两个区间收益的差，不称风险调整后的 alpha。

个股复权、指数价格/全收益类型在图表旁清楚展示；指数接口没有 adjust，不发送该参数。没有共同可比口径时只并列展示各自表现并说明差异，不能据此宣称跑赢可投资基准。缺失交易日不随意前值填充成零收益；起止日对齐和实际有效窗口可见。

板块广度只基于所选板块的当前成分与可得行情，展示上涨/下跌/平盘/未知数量、已覆盖 n/当前成员 N。默认用户明确点击后批量查询一次，不三秒轮询全市场。无权重不计算指数涨跌贡献；没有历史成分序列时回看当前成员必须标“当前成分回看”，不能当时点真实行业样本或回测结果。

可从已选板块已取成分建立有限的本地关联，用于关注对象关联阅读；不把规划中的个股反查板块接口当现成功能，不在启动时遍历所有板块构造全市场关系网。

### 2.3 基金披露持仓穿透与重叠

新增 `backend/app/analysis/fund_overlap.py`、`research/fund_research.py`。用户选择 2–5 只基金，最多 10 只；展示披露期末、披露日、已披露持仓、可见覆盖比例、行业/资产配置。目标是发现“看似不同的基金是否暴露于相同证券”，不是计算用户真实账户资产配置。

先调用 stock-report-dates 发现实际 report_type/end_date，再读历史；不得硬编码报告类型含义或拿每只基金各自最新且不同时期的持仓算同步重叠。尽量选择共同报告期；无共同期间时并列展示各期持仓并明确不计算同步重叠率。

在权重定义均确认是相对基金净资产且报告期一致时，已披露重叠权重定义为 `sum(min(w_A,s, w_B,s))`，仅对共同已披露证券求和；未披露部分不补零也不重新归一到 100%。该结果只能表述为同披露期、该权重口径下可见的重叠下限，不是完整组合真实重叠。权重定义未知时仅展示共同证券和原始比例，不输出这一计算。

披露汇总股票占比与已返回个股权重之和分别显示；只有同口径完整可核对时才说覆盖了股票部分多少比例。行业口径不同则并列，不将概念标签当标准行业。重复证券合并需核对市场/资产类型，不凭纯 ticker 合并跨市场标的。

跨期权重变化显示“披露权重变化”，可注明市场价格、申赎、披露范围都可能影响；没有交易数量和区间成交证据不能写成经理买入/卖出。A/C 等份额共享组合只有正式资料确认才关联，份额各自净值/费率/规模不重复累加；持有人 merged/separate 两种口径也不相加。

### 2.4 基金质量、经理任期与指数基金比较

新增 `backend/app/analysis/fund_quality.py`，扩展 fund_research。用户指定比较组，从成立时间、规模、费率结构、经理任期、净值表现、回撤和披露集中度理解差异。全部结果允许部分可用，不能因为没有持仓就拒绝净值分析。

基金净值请求 range 使用官方 week/month/tmonth/hyear/year/twoyear/tyear/fyear 枚举，缺省只返回最新一点；选任意日期窗口时只能在已取且覆盖的序列中裁剪，不把日期字符串传给 range。unit_nav、adj_nav 与累计净值不混用。用复权净值计算时注明供应商口径；缺复权序列不能将除息后的单位净值跌幅直接称投资损失。

确定性计算包括同窗口累计变化、峰谷回撤、当前距前高幅度、回撤恢复是否在观测期发生。样本覆盖不足、净值异常、期间不完整就标缺口。年化收益仅在不少于一年且口径可比时给出；波动率至少 60 个可比日收益观察值，使用样本标准差及明确的 252 交易日假设，非连续/不规则序列不强行年化。首版不算缺无风险利率口径的夏普比率。

供应商 returns/drawdowns 固定区间结果与本地自定义窗口计算分开标记，只有范围、截止日和口径一致才校对；不为了数值一致而调公式。现任经理只对应其实际任期与共同管理范围，不把基金全部历史归给现任。任期缺失时经理归因 unavailable，但基金历史仍可展示。

指数基金比较先确认跟踪对象、指数类型、共同区间和净值日期。没有匹配的全收益基准/适用的收益口径时，不能称精确跟踪误差或跟踪差异；只给带限制的并列走势。基金费用按实际费率条件展示，不能把已体现在净值中的费用再从历史收益重复扣除。

`track_index_pe_ttm_five_year_percentile` 仅在适用基金实际返回时作为“跟踪指数 PE TTM 五年分位”显示，不能称基金净值分位。没有 IOPV 不算实时折溢价；不同日期的二级市场价和净值不拼出实时套利指标。REITs/债券/货币基金不强套股票基金指标，说明适用范围。

### 2.5 与用户研究对象相关的市场复盘

新增 `backend/app/analysis/market_context.py`、`research/market_review.py`。用户选择日期、标的或关注对象、可选板块，生成三层复盘：可核对的行情/名单事实、供应商原有解释、需要原文核实的研究问题。关注列表如果 05 尚未实现，允许本页直接选标的，不制造跨阶段依赖。

龙虎榜按标的、统计窗口、榜单原因等规范化键去重；单日/三日不同口径不相加，席位净额不能代表全市场净流入。连板天梯每梯队最多四只，不据此统计全市场连板数量；涨停/炸板等池只有返回覆盖足够且已去重时才统计“该池样本”。

当日异动解释不支持历史回查时，历史研究报告标该维度不支持；不得把今天解释移植到过去。热度/排名变化只说明关注变化，不预言未来涨跌。搜索补充仍须符合 04 授权、预算、原文和日期校验。

### 2.6 页面与接口

新增 `backend/app/api/sectors.py`、`api/funds.py`、`api/market_review.py`；新增 `frontend/src/api/sectors.ts`、`api/funds.ts`、`api/marketReview.ts`，`pages/Sectors/index.tsx`、`pages/Funds/index.tsx`、`pages/MarketReview/index.tsx`。任务复用 POST `/api/research/tasks`，type 为 sector_relative/fund_overlap/fund_quality/market_review，不能每种功能再建独立 Agent 和事件协议。

资料读取使用 GET `/api/sectors/{id}/research`、`/api/funds/{id}/research`、`/api/market-reviews`，仅返回本地记录；所有外部刷新通过显式任务。UI 默认显示数据日期、披露期、覆盖分母和原文入口；跨期不可比和净值口径限制必须靠近结果，不能只放折叠免责声明。

图表共用 `components/ResearchChart/index.tsx`；05 已建立时复用，05 尚未执行则按其约定在本阶段创建同一 ECharts 薄组件，后续 05 复用，不重复安装图表库。重叠矩阵、净值曲线、回撤曲线和涨跌分布都提供对应数表与缺口。

## 3. 禁止事项与兼容性

不把披露持仓叫实时持仓，不据当前成分回看生成无偏历史结论，不拿热榜和龙虎榜提供交易信号。不填补没有 IOPV、历史成分、权重、无风险利率和真实交易记录所不能支持的分析。不同基金类型、不同日期和不同口径比较必须有条件边界；继续使用统一报告、缺口、API 设置和手动再分析。
