# 08 — 安全鲁棒性与自带密钥交付验收

## 1. 摘要与前置阅读

优先级 P0（交付门槛）；预计 3–4 批；直接依赖 01–07；目标：证明新安装可独立使用、用户只使用自己的 Key、缺数据和坏输出可恢复，明确实际联调与未来公网运行的边界。

前置阅读：现有 `backend/app/main.py`、`settings.py`、`security.py`、`errors.py`、`storage.py`、`scripts/test_backend.ps1`、`scripts/start_all.ps1`、`启动FinSight.bat`、`frontend/src/api/client.ts`、`README.md`；01–07 新增凭据、适配器、研究图、JSON、上传、事件流、导出及对应测试。阅读两份 API/模型调研里的实测边界和许可结论，不能把文档能力当账号真实权限。

## 2. 任务详情

### 2.1 离线故障矩阵

新增 `tests/integration/test_research_acceptance.py`、`test_failure_recovery.py`；复用各阶段 MockTransport、任务事件与人工可复算样例，不使用真实账户或网络随机结果做离线断言。文件和数据库在本机 `.cache/` 隔离目录创建，不读取正式配置。

| 场景 | 通过标准 |
| --- | --- |
| 一项字段 null/缺一张报表/缺公告 | 其他维度照常分析，缺口说明精确到字段、期间和影响 |
| 全部业务源无数据 | 有效模型给条件框架与取证清单，明确无公司事实依据，用户可保存/补充 |
| 未配置、权限不足、额度不足、过期 | 呈现不同原因与对应设置入口，不借用其他 Key，不循环调用 |
| HTTP 200 业务失败、HTML 错页、字段变更 | 不误认为成功或空值为零；保留其他结果 |
| JSON 围栏/解释文字/转义/双编码 | 有边界的解析路径正确，原文和清理诊断不暴露秘密 |
| 多对象/重复键/缺括号/错误类型 | 不猜测执行工具；局部恢复后仍坏则保留明确未验证文本 |
| JSON 合法但数字/证据/期间冲突 | 语义校验失败，不进入已验证指标/结论 |
| length/断流/无结束标记 | 未完成状态可见，合法章节保留，恢复次数受限 |
| 思考很长/总耗时超过旧 120 秒 | 有流活动时不中断，实际请求使用最大预算，取消始终可用 |
| 刷新、断线重连、重复提交 | 继续读取同任务，不重复生成或收费 |
| 进程重启 | 标中断并保留公开结果；用户主动恢复，不自动重放付费请求 |
| 来源冲突、修订财报、用户改数 | 保留出处与不同版本，不静默覆盖 |
| 外部提示注入、恶意工具参数 | 不改变来源授权、读文件/执行代码或外发 Key |
| 恶意附件、SSRF、下载/解析超限 | 拒绝对应资料，主服务与其他分析可继续 |
| 导出与删除 | 缺口/许可限制保留；无敏感夹带、越界访问或误删共享证据 |

长时间用虚拟时钟/受控异步流验证，不在测试里真的等待数分钟。至少一份输出超过旧 262144 字符边界；无需为了测试最大 token 参数生成数十万 token 的真实付费回答。数值样例使用显式演示标的，不能被页面当真实行情。

### 2.2 五项用户要求的端到端验收

建立五条独立、可重现的流程，证据记录到本机 `.cache/验收/`，简短结论写入 `docs/功能使用与验证说明.md`。该文件是产品验证说明，不设计划执行状态机或回执。

1. 缺财务报告仍完成价格/风险框架分析 → 展示缺口 → 上传用户资料并确认口径 → 不自动外发 → 用户点击再分析 → 新旧报告并存。
2. 模型返回代码围栏、错误 JSON 和被截断 JSON → 清理/有限格式修复/分节恢复各走正确分支 → 未通过的部分不会被当正式数据。
3. DeepSeek、GLM、Qwen 的默认 output_policy=maximum → 检查真实出站 payload 与有效预算 → 验证不是前端显示大值而服务端仍限制 32768/120 秒。
4. 同花顺某项 unavailable → 只在用户已选且授权时使用 Tushare/搜索/用户资料 → 标来源、许可和冲突 → 所有补充源不可用时仍完成已有证据分析。
5. 全新实例进入同一个“模型与 API 配置”页 → 用用户自己的 Key 配置模型、同花顺、博查/Tavily、可选 Tushare → 各能力独立测试 → 删除配置后无隐藏环境/开发者 Key 回退。

解析成功率、章节完整率、数据覆盖和实际调用数分别观察，不合成一个掩盖问题的“成功率”。首批人工审阅至少覆盖公司、同行、理由复核、板块、基金重叠、基金质量和市场复盘各一份，同时包含数据稀疏情形；检查事实引用与推断界限，不以文风流畅代替金融正确性。

### 2.3 凭据隔离与真实联调

新增 `tests/integration/test_byok_isolation.py`、`test_sensitive_data_boundary.py`。两个隔离本地实例分别配置无效夹具 Key A/B，Mock 检查请求只使用对应实例/配置；切换来源、编辑留空、清除、删除、禁用、根密钥缺失、导入环境均验证。历史报告可读不等于仍能调用已删除凭据。

检查服务端日志、错误响应、SQLite 非凭据字段、证据、SSE、浏览器持久化、导出文件、前端构建产物，确保不包含夹具秘密或 reasoning_content。扫描结果只报告文件名和规则，不打印疑似密钥正文；真实日志/数据库不上传外部分析平台。固定官方客户端不能把 Key 带到重定向或用户提供 URL。

真实联调新增到明确 requires_api/requires_llm 标记下，仅在用户配置自己的 Key 并主动授权当前测试范围后执行；普通测试、启动、健康检查不会运行。按能力报告“未配置/未测试/通过/权限不足/协议不兼容”，不将后两项笼统写成实现成功。

模型最大值测试采用最大参数配短回复提示，验证服务接受参数及结构化/工具协议；DeepSeek 384K 的整数值必须从官方明确契约或实际参数响应确认，不能把候选 393216 未验证地写成实测。流式长输出正确性主要由离线模拟验证，真实短探针不声称证明整段最大长度稳定生成。模型服务商更改上限时更新唯一能力目录、来源日期和相关测试。

金融源真实测试只取少量指定标的/时期；Tushare 财务/审计/主营/历史估值、同花顺基金/财务等权限分别测；Bocha Search、Tavily Search/Extract 分别测。未拥有的权限不是自动购买理由，不能拿别人的 Key 补测。

### 2.4 本地使用说明与启动验证（不制作发布包）

本轮不创建安装包、压缩包或发布目录。保留现有启动脚本和锁定依赖清单，按 README 在当前本机目录创建 `.venv`、安装依赖、执行前端构建并启动。原有“安全关闭本项目旧进程 → 启动 → 健康检查 → 默认浏览器”保持成立；端口占用不杀其他软件，断网/无 Key 能打开首页与设置。

API 配置卡全部可见，未填 Key 清楚标未配置；无开发者兜底服务，用户决定是否申请付费源。第一次保存时在自己的本地实例生成根密钥，不复制开发机根密钥或数据库；只写入用户刚填的凭据。

更新 `README.md`、`docs/README.md`、`docs/模型服务商接入说明.md`，新增 `docs/功能使用与验证说明.md`、`docs/API与数据使用边界.md`。分别说明：配置/申请入口、能力与许可、缺口补充、长输出费用、再分析版本、导出/删除、Key 丢失、故障恢复和真实联调范围。发布文档只写实际已实现/验证的状态。

### 2.5 本地交付与公网服务边界

本计划交付的是每位用户运行独立实例并自带 Key 的本机应用。当前本机会话不是账号认证；不能通过改 Host 白名单、隧道或绑定 0.0.0.0 直接上线多人共用。以下属于公网服务上线前必须另行完成的安全范围，本轮没有这些实现时公网验收明确不通过，而不是默认安全：

| 公网必要条件 | 本轮边界 |
| --- | --- |
| 真实登录、会话、账号恢复与 CSRF/滥用控制 | 保持回环绑定，不冒充用户体系 |
| 配置、任务、证据、附件、缓存、事件和导出的用户级所有权检查 | 本轮只验证隔离本地实例；不能宣传为 SaaS 多租户隔离 |
| 服务端密钥管理、租户隔离、审计、备份与删除 | 本机 Fernet/`.env` 方案不是托管平台的完整密钥治理 |
| 用户级限额、计费边界、文件解析隔离和出网限制 | 本轮实例级限额不能充当公网配额控制 |
| 数据源商业授权、外部 LLM 处理权、隐私/删除条款 | BYOK 仍须满足许可；Tushare 未取得适用授权不能进入商业发行 |

保留模块边界以支持今后添加账号所有权，不现在搭建未要求的云平台。公共服务版本需要用户明确选择部署形态后单独立项；本轮不创建开发者付费代理、不替所有用户承担模型/搜索/金融 API 费用。

## 3. 禁止事项与兼容性
