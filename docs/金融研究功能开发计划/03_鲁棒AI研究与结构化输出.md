# 03 — 鲁棒AI研究与结构化输出

## 1. 摘要与前置阅读

优先级 P0；预计 4–5 批；直接依赖 01、02；目标：选标的、问问题、分析已有证据、列出缺口、补充文字、主动再分析，形成第一条完整且可中断恢复的产品流程。

前置阅读：现有 `backend/app/agent/model_factory.py`、`provider_requests.py`、`api/model_config.py`、`security.py`，`frontend/src/api/client.ts`、`pages/Settings/ModelPlayground.tsx`、`App.tsx`；01 的预算/流式协议；02 的 `market_data/service.py`、`analysis/`、`research/evidence_models.py`、`evidence_store.py`、`repository.py`；本计划 `调研资料/模型输出上限与JSON解析依据.md`。本阶段使用已经安装的 LangGraph 与 Pydantic，不搭第二套编排框架。

## 2. 任务详情

### 2.1 缺数据继续工作的明确契约

新增 `backend/app/research/models.py`、`service.py`、`tasks.py`、`reports.py`、`supplements.py`；任务执行状态和报告数据覆盖程度分别保存：

```text
Task.status = queued | running | completed | interrupted | cancelled | failed
Report.coverage = sufficient | partial | no_business_evidence
Section.status = supported | conditional | unavailable
Output.integrity = validated | partial | unstructured | truncated
```

这些是产品业务状态，不是本计划的执行管理机制。Task completed 只说明本轮结束，不能让页面把 partial 报告显示为“数据完整”；一次输出被截断也不使已经通过校验的其他章节消失。

| 输入情况 | 必须产生的结果 |
| --- | --- |
| 财务有、价格无 | 继续经营与财务分析；不判断当前估值，列缺失日期/字段与影响 |
| 价格有、财务无 | 可描述走势、波动和历史回撤；不把涨跌解释成业绩变化 |
| 公告不足 | 报告可检验假设及待核实事项，不能直接认定事件原因 |
| 所有业务数据都没有 | 有效 LLM 仍给针对问题的分析框架、用户假设下的条件分析及取证清单；明确没有公司事实依据，不编造指标和结论 |
| 用户不愿补数据 | 允许保留、保存、导出当前局部结果，不阻止继续使用 |
| 无有效 LLM/模型完全离线/服务商过滤 | 保留本地事实、计算、缺口和已完成章节，明确“未完成 AI 分析”的原因；不伪造模型已分析，也不绕过安全限制 |

系统提示必须明确：数据缺失本身不能成为整体拒绝分析的理由。最终页面中的缺口清单由程序汇总 DataGap 与章节校验结果，LLM 仅补充解释，不能因模型漏写而消失。每项包含“缺什么、影响什么、已有替代证据、可以怎样补”；展示数据来自哪些时期、哪些维度根本没有证据，不输出无依据的单一置信度分数。

内容验收要求至少产出一项有证据的分析或针对用户问题的条件研究框架，不能整份只有“请补齐数据再分析”。模型仅因缺数返回此类空答时，作为内容不合格在同一节有限修复预算内重生成，明确给定已有材料和条件分析任务；不能无限重试，也不能用关键词匹配把安全过滤当缺数拒绝绕过。模型持续不可用时保留本地研究清单并明确 AI 失败，不伪称实现了模型分析。

### 2.2 有界研究图与只读工具

新增 `backend/app/agent/research_graph.py`、`tools.py`、`prompts.py`、`state.py`。用 LangGraph StateGraph 组织身份确认、证据收集、确定性计算、分节解释、校验与定稿；工具仅暴露明确 schema 的领域方法，例如 fetch_financials、fetch_prices、fetch_valuation、read_evidence、calculate_metrics。模型没有任意 HTTP、SQL、Python、shell、文件路径工具，拿不到 Key。

来源失败返回结构化 DataGap 给模型；有限取数结束后转入已有材料分析，不能停在“请补数据后再来”。支持工具的官方模型可以自主选择已授权工具；自定义模型没有稳定 tool calling 时切换为程序固定取数模板后生成解释，并显示能力降级，不要求用户换模型才能使用。

启动任务前展示所选模型、来源、数据外发、默认最大输出策略和调用数量预算。初版默认最多 24 次 LLM 请求、24 次结构化取数、6 次搜索、3 次正文提取；搜索/提取尚未接入或未经授权则为 0。每个逻辑取数最多两次暂时错误重试；重试也计入预算。工具回合最多 8 轮。预算是可在启动前调整的明确产品约束，不是虚构的费用保证；上下文预估、已知 token 用量与服务商返回 usage 分开展示。

进入正文分析前预留足够请求次数给选定章节及有限修复；不得把全部预算花在搜索上而拒绝总结。达到预算时不再新开付费请求，保留已完成内容并提供用户主动继续入口，不强行截断已经授权、正在输出的单次模型回复。实际金额只有配置了可信单价才估算，未返回 usage 不显示 0 元。

外部内容一律当证据，公告、网页或附件中的“忽略指令”“调用地址”等文本不能改变工具白名单、来源授权或系统提示。内容进入模型前提供 provenance 和数据类型；严格限制每条工具结果大小，按 evidence ID 读取必要片段，不把整份数据库塞入上下文。

### 2.3 报告契约与数值职责

新增 `backend/app/agent/output_models.py`、`output_validation.py`。采用有 schema_version 的分节报告，章节如事实概览、财务质量、价格估值、风险与反证、待验证事项；缺少资料时该章节可以 conditional/unavailable，不能强迫填满所有数字。

```text
ResearchReport
  id / version / parent_report_id / task_id / question / scope
  model_snapshot（不含 Key）/ created_at / evidence_ids
  metrics（由程序计算）/ sections / data_gaps
  coverage / output_integrity / limitations

ReportSection
  id / title / status / summary
  claims[]: kind(fact|derived|inference|user_assumption), text,
            evidence_refs[], metric_refs[], gap_refs[]
  counter_evidence[] / follow_up_questions[]
```

事实数字由程序指标块渲染，模型通过 metric_refs 引用，避免让模型重新抄写整张数值表。业务校验检查引用存在、属于本任务授权证据、标的/期间/单位一致、事实与计算类论断有可用依据；模型正文出现与被引指标冲突的数字时标记冲突并修复该节。不能只因 JSON 可解析就将内容当作事实。没有证据的解释必须标为推断/假设，不能用通用免责声明掩盖错误引用。

校验可以发现引用和数值等确定性错误，不宣称能自动保证全部语言推理正确。每节保留原文出处入口，用户能检查反证；模型自评不替代源数据与程序验证。

### 2.4 JSON 解析管线

新增 `backend/app/agent/json_parser.py`，复用 stdlib json 和现有 Pydantic。先按 01 能力目录选择供应商已支持的 JSON Schema 或 JSON object 模式；没有此能力时使用明确 schema 的提示和同一解析管线。发送原生 response_format 与 Prompt 中“输出 JSON”的要求保持一致；不得向未支持的模型硬发参数。

按以下顺序处理报告章节：

1. 用增量 UTF-8 解码器/SSE 解析器聚合字符串、choice 与 tool index，保留 finish_reason、usage 和错误。不要逐个 token 对半截 JSON 调用正式校验。
2. 正常结束后先严格 `json.loads`；拒绝重复键、NaN/Infinity、非对象根、超限深度/集合和不允许的字段。长度限制按 01 有效输出预算计算，工具参数另有更小边界。
3. 仅允许不改变内容含义的清理：首部 BOM/外层空白、完整包围内容的一对代码围栏；或用 JSONDecoder 的边界解析从解释文字中找出唯一完整候选。正确处理字符串内部括号、转义引号和多行文本，禁止贪婪正则截取首尾大括号。
4. 明确检测一次额外 JSON 字符串编码时，最多额外 decode 一层，记录清理类型。多个互相竞争的 JSON 对象、缺失括号、未闭合字符串不能任取一个宣布成功。
5. 使用 Pydantic strict/extra=forbid 校验章节 schema，再做 2.3 的证据/期间/语义校验。供应商数字的受控转换属于 02 规范化层，不在这里随意转换日期、布尔、空值和数字字符串。
6. 有完整文本但格式不合格时，最多调用同一模型一次“只修复该节格式”，传原内容、schema 与简短错误；不重新取数、不换模型、不重新启动全图。修复后再严格校验，涉及数值、证据或论点变化的内容不能靠格式修复自动升格为已验证。
7. 仍失败则保留其他合法章节；将这一节作为“未通过结构校验的原始文本”可展开查看，只做安全纯文本渲染，不导入指标库、不执行其中内容，程序缺口仍完整显示。用户可主动重试该节或保留现状。

首版不新增 json_repair 依赖：它可能补出值或结构，不能作为金融事实/工具执行的信任边界。Pydantic 的 partial JSON 能力只用于明确标注的流式预览，绝不能证明供应商输出完整。禁止 eval、exec、YAML 解析兜底和全局替换单引号。

工具参数走更严格路径：完整结束、唯一调用 ID、合法工具名、严格 JSON/schema/范围全部通过才执行；不做宽松 JSON 修补。坏参数向对应 call id 返回结构化错误，允许模型在剩余预算内改正一次；仍错则跳过该工具、记录缺口并继续已有证据分析。相同工具/相同规范化参数的重复调用复用本任务结果，防止循环收费。

### 2.5 长输出、截断与续写

报告按章节独立生成和验证，界面组合成完整报告；每次研究生成仍按 01 使用当前模型实际最大输出，不因分节而重新设成 8K。根据模型/模式 context cap 打包输入，显示因上下文不足而降低的实际预算。不能把“开到最大”写成“绝不会截断”。

`finish_reason=length`、无正常结束、流中断、服务端异常终止或达到安全字节上限均标 incomplete；即便碰巧解析出合法 JSON，也不能把整节判完整。已完成章节原样保留；截断章节显示状态和最后更新，用户始终能取消。

自动恢复最多一次且计入任务启动时已展示的预算：携带章节 ID、原证据和已确认结构重写该章节，不拼接两段半截 JSON；重新生成通过校验后替换该节的候选内容。超过次数或预算则显示“继续完成此节”，由用户启动新的恢复请求。不能靠不停发送“继续”形成无限费用循环，也不因一个章节失败重跑整份报告。

DeepSeek 等工具协议需要的 reasoning_content 只保留在该任务后端内存，回传给相同模型时维护原 assistant/tool 配对与 call id；不持久化隐藏推理。Graph 不使用会把完整消息状态落盘的 checkpoint；SQLite 保存业务进度、证据和公开结果。进程重启后新建分析上下文，明确不是恢复原模型的隐藏推理过程。

### 2.6 异步接口与研究页面

新增 `backend/app/api/research.py`、`research/events.py`；新增任务、公开进度事件和报告表，由现有 storage 迁移。沿用单进程 asyncio 任务集合及信号量，默认同一实例最多一个活跃生成任务，其余排队；退出时取消并收尾。无需 Celery/Redis。

| 本地端点 | 契约 |
| --- | --- |
| POST `/api/research/tasks` | 保存 client_request_id、请求哈希、范围/授权/预算后返回 202 + task_id |
| GET `/api/research/tasks/{id}` | 读取状态与公开进度，不触发新调用 |
| GET `/api/research/tasks/{id}/events?after={seq}` | 带会话头的 SSE，心跳与增量公开进度；无隐藏推理 |
| POST `/api/research/tasks/{id}/cancel` | 幂等取消，关闭在途流，保留可读部分 |
| GET `/api/research/reports/{id}` | 离线读取报告和缺口 |
| POST `/api/research/reports/{id}/supplements` | 保存本地文字/数值说明，不自动外发或再分析 |
| POST `/api/research/reports/{id}/reanalyze` | 明确选择补充资料/来源/模型后创建子版本任务 |

同一 client_request_id + 同一请求内容返回原任务，不二次收费；同 ID 不同内容返回 409。浏览器断线只重连/轮询，不重放生成 POST；后端重启将 running 标 interrupted，不能启动时自动再次付费。公开事件保留 seq 以便刷新后续读，旧事件清理时以任务快照恢复，不承诺 token 字节完全重放。

新增 `frontend/src/api/research.ts`、`pages/Research/index.tsx`、`components/ResearchReport/index.tsx`、`components/DataGaps/index.tsx`；扩展 01 已新增的 `api/eventStream.ts`，修改 App、Layout 和 Home 导航。使用 fetch 携带已有内存会话头读取 SSE，不沿用 Axios 130 秒等待整份报告；复用已锁定 `eventsource-parser` 解析分块事件。SSE 只传公开进度/章节预览，不能传 reasoning_content、Key 或完整 SDK 异常。

渲染事实卡、章节状态、来源抽屉、缺口、取消/继续、任务费用用量。原始模型文本默认按 React 安全文本展示；不为 Markdown 便利引入直接 innerHTML。窄屏允许表格横向滚动，关键缺口和按钮不能被折叠后消失。

### 2.7 用户补充与主动再分析

本阶段先支持文字和小型结构化说明，04 扩展文件。用户可按某一缺口填写数据、日期、单位、来源说明，也可添加自己的观点；保存为 user_provided/user_assumption，不自动改写官方证据。

补充保存后展示“已保存，尚未再分析”；用户可以选择不补、只补部分、重新取数、只用已有证据、更换自己配置的模型，再点击“基于这些资料再分析”。新版本引用 parent_report_id 和选定 supplements，保留上次问题及范围，明确本次变化。原报告不可变，新分析失败不覆盖旧结论；新旧差异注明来源变化、数据变化、假设变化与单纯模型措辞变化。

## 3. 禁止事项与兼容性

不以“数据不齐”为全任务错误，不把非结构化文本当校验成功，不通过截断字符串凑合法 JSON。不得降低安全控制来迎合“不能拒绝工作”；正常能力/安全失败有明确说明。不能读取/执行网页指令、私自启用新数据源、换模型或发送私有资料。保留 01 设置、02 资料预览及一键启动功能。
