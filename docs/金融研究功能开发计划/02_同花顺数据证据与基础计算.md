# 02 — 同花顺数据证据与基础计算

## 1. 摘要与前置阅读

优先级 P0；预计 3–4 批；直接依赖 01；目标：把用户选定标的的可用数据转成有口径、有来源、可复算的研究证据，并将缺失转换为可解释的缺口。

前置阅读：现有 `backend/app/main.py`、`dependencies.py`、`storage.py`、`settings.py`、`errors.py`、`security.py`；01 新增的 `api_config/` 与 `credentials.py`；`frontend/src/api/client.ts`、`pages/Home/index.tsx`。阅读本计划 `调研资料/同花顺能力与功能边界.md`，对照官方 [REST 契约目录](https://github.com/HiThink-Tech/Financial-API/tree/main/docs/api) 中 meta、prices、financials、valuations、calendar；不要只照在线首页概览实现。

## 2. 任务详情

### 2.1 主源客户端与能力测试

新增 `backend/app/market_data/ths_client.py`、`models.py`、`service.py`、`identity.py`、`cache.py`。使用已有共享 httpx 客户端和 01 凭据服务，固定 HTTPS origin `https://fuyao.aicubes.cn`，认证头 `X-api-key`；不打印 header、原始异常或带凭据请求。

按官方业务 `code`、HTTP 状态和响应 schema 三层检查。HTTP 200 不等于业务成功；空数组、字段 null、非 JSON、权限不足、未覆盖资产、限流、超时分别记录。单次 HTTP 连接 10 秒、读取 30 秒；只对幂等取数的网络暂时错误、429/可重试 5xx 最多重试两次，遵守 Retry-After 和任务剩余预算。401/403、业务权限/参数错误不重试；取消、源被禁用后停止后续请求。

先实现以下固定能力，再由 06 扩充指数与基金，不一次遍历全部端点：

| 能力 | 上游端点与用途 |
| --- | --- |
| 标的检索 | `/api/meta/tickers/search`，按名称、代码、交易所和资产类型消歧 |
| 股票快照 | `/api/a-share/prices/snapshot`，只用显式 thscodes 批量模式 |
| 日线历史 | `/api/a-share/prices/historical`；起止日期、复权和周期显式传递 |
| 当前估值 | `/api/a-share/valuations/snapshot`，只表示当前可得指标 |
| 财务三表 | `/api/a-share/financials/` 下 income-statements、balance-sheets、cash-flow-statements |
| 财务指标 | `/api/a-share/financials/indicators`，保留 abilities 指标字典与单位 |
| 交易日期 | `/api/a-share/calendar/trading-days`，用于窗口和交易日检查 |

金融数据设置卡中分别测试检索、行情、财务、估值；指数/基金在 06 激活。用户点击测试前看到标的、请求数量和可能计费，测试记录只保存脱敏状态及时间；一个端点可用不能推定整个账号权限完整。

### 2.2 身份、日期与数值口径

用户确认唯一标的后保存 `SecurityIdentity`：供应商代码、代码、名称、交易所、资产类型、币种、确认来源。多候选让用户选择；没有唯一身份时保留问题、给候选或研究框架，不能擅自选择同名股票取数。禁止根据名称猜交易所后缀。

新增 `backend/app/market_data/normalization.py` 和 `field_dictionary.py`。每个数值保留 raw_value、normalized_value、unit、currency、period_end、disclosed_at、basis、source_field；百分数统一内部比值，展示时按单位格式化。金额使用 Decimal 参与财务计算，JSON 用明确的十进制字符串契约传递；非有限值、无法解释的占位符标缺口。null、零、负值三者不同。

默认取最近四期年报和近一年日线；用户可明确选择官方支持的其他范围，请求前显示预计数量。三表 recent-limit 与 start/end 模式互斥；毫秒时间戳、端点日期和 Asia/Shanghai 边界集中转换。季度数据是累计还是单季未经确认时不做差分推导，年报缺失也不能用季度数冒充全年。

抓取时间不冒充行情时间，估值顶层最新时间不冒充每个字段的时间。处理乱序、重复日期、同一报告期不同披露版本；原始证据不改写，默认采用当前已知最新披露版本并显示披露时间。没有完整历史披露版本时不提供“截至过去某日当时可知”的结论。

### 2.3 数据结果与缺口契约

新增 `backend/app/research/evidence_models.py`。所有取数返回相同的小型结果，不向上抛出可预期的数据不足异常：

```text
DataResult
  status: available | partial | unavailable
  records: 按对应领域 schema 校验后的记录
  evidence_ids: 本次结果引用
  gaps: DataGap[]
  requested_scope / returned_scope / source_profile_id

DataGap
  id / dimension / fields / security_id / period
  reason: not_configured | permission_denied | rate_limited | timeout
          | not_published | unsupported | invalid_response | basis_unknown
          | source_conflict | stale | not_applicable
  impact: 不能验证或计算什么
  blocking_for: 受影响的具体指标或论断，而非整个研究任务
  remedies: 配置来源、上传、文字补充、改范围或保留缺口
```

纯程序错误仍进入安全错误处理和开发日志，不伪装成“供应商无数据”。DataGap 由程序建立，03 的 LLM 不得删除它；没有替代源时继续返回其他成功部分。数据过期记录 age 与请求的时效要求，由报告注明，不悄悄当最新数据。

### 2.4 可检查的证据和缓存

新增 `backend/app/research/evidence_store.py`、`repository.py`；在 `Storage.initialize()` 新增 evidence、data_gaps、data_cache 索引表。证据至少包含 ID、source/provider、profile_id 的内部引用、脱敏 endpoint/参数、标的、范围、源时间、抓取时间、口径、内容哈希、schema_version、storage_policy、许可说明与本地文件相对路径。

原始业务响应和规范化记录分开；剔除任何 credential 后才能保存。只有服务条款允许保留时才写原文，使用 `data/evidence/<随机ID>/`、临时写入和原子替换。`full|excerpt|reference_only|ephemeral` 按 04 的许可契约贯穿；授权不明确时不默认永久保存全文，引用/摘要也必须符合对应条款。原始文件保留策略受限时保留允许的出处、指标和哈希，并标明不能完整复现。

缓存键包含 provider、profile_id、credential_version、endpoint、规范化参数、schema_version 和口径；换 Key/账号不得复用另一账号的实时请求缓存。数据保存与缓存过期是两件事，过期缓存不能覆盖历史报告证据。默认快照 60 秒、搜索标的 24 小时、历史/财务 6 小时，页面显示这些是本地刷新策略而非上游时效承诺；用户可手动刷新。

已经合法保存的历史证据可离线重读，即使 Key 被删除也不消失；新任务若选择复用，明确显示数据日期，不把本地旧证据当本次联网成功。不得用缓存绕过已撤销的数据使用许可。

### 2.5 最小确定性计算和可见结果

新增 `backend/app/analysis/models.py`、`price_metrics.py`、`financial_metrics.py`。计算结果记录 formula_id/version、输入 evidence/field 引用、期间、单位、结果、有效性和缺口。首批仅实现：同口径区间价格涨跌、最大回撤；年报营收/归母净利润变化；净利润率；资产负债率；经营现金流与净利润的关系。

正基数同比才显示常规百分比；基数为零/负值时显示绝对变化和盈亏变化，不产生误导增长率。经营现金流与利润比使用匹配的合并净利润，不能无说明混用归母口径；利润非正时不把比值当质量排名。`total_debt` 仅对应负债合计；不输出未经证据支持的有息负债率。行业适用性留到 05 扩展。

新增 `backend/app/api/market_data.py`，注册 POST `/api/data/resolve`、POST `/api/data/fetch` 和 GET `/api/evidence/{id}`。外部检索/取数必须是用户主动触发且包含来源选择；读取已保存证据不联网。GET 仅返回允许展示的规范化数据/出处，文件路径由 ID 在服务端解析，禁止任意路径参数。

新增 `frontend/src/api/marketData.ts`、`components/SecurityPicker/index.tsx`、`components/EvidenceDrawer/index.tsx`；Home 增加“选标的、取研究资料”小入口。表格显示时间、单位、缺口和来源，不做暂时假的 AI 报告。后续 03 直接复用此入口。

## 3. 禁止事项与兼容性

不批量导入全市场，不启用规划中接口，不用搜索摘要填结构化金额，不补零，不将缺失期插值成财务数据。不上来就增加 pandas/金融 SDK；当前 stdlib、Pydantic、httpx 足以完成此阶段。不得改变 01 的凭据契约、普通启动行为和既有模型试用。
