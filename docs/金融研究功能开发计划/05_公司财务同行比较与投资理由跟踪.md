# 05 — 公司财务同行比较与投资理由跟踪

## 1. 摘要与前置阅读

优先级 P1；预计 3–4 批；直接依赖 01–04；目标：把基础研究闭环变成可持续使用的公司研究工具，帮助用户理解利润质量、比较差异和验证自己的投资理由。

前置阅读：02 的 `market_data/field_dictionary.py`、`normalization.py`、`analysis/financial_metrics.py`；03 的 `agent/output_models.py`、`output_validation.py`、`research/reports.py`、`service.py`；04 的 `tushare_client.py`、`research/supplements.py`；`frontend/src/pages/Research/index.tsx`、`components/ResearchReport/index.tsx`、`components/DataGaps/index.tsx`；现有 App、Layout、storage。阅读 `调研资料/同花顺能力与功能边界.md` 和 `调研资料/补充数据源调研与选型.md`。

## 2. 任务详情

### 2.1 公司财务体检

新增 `backend/app/analysis/company_quality.py`、`industry_applicability.py`；扩展已有 financial_metrics，不再建一套公式实现。新增 `research/company.py` 组织证据与固定章节，Agent 只解释程序结果和材料。产品重点是“哪些变化值得核实”，不给来源不明的健康分或自动买卖结论。

| 维度 | 首批结果 | 数据不足时的处理 |
| --- | --- | --- |
| 增长与盈利 | 营收、归母利润、毛利/净利率变化；扣非与归母利润对照 | 缺扣非则明确不能区分非经常损益影响，不猜一次性收益 |
| 利润与现金 | 同期经营现金流、合并净利润及多年匹配情况 | 非正利润单列金额与趋势，不用异常比率排序 |
| 资产质量线索 | 应收/存货相对营收变化、已提供的周转指标 | 口径/期初余额不足不自造周转天数；线索不等于造假认定 |
| 负债与偿付 | 负债合计、资产负债率、可用流动指标、现金位置 | 有息负债/到期结构缺失则不能推断再融资压力大小 |
| 经营投入 | 研发/销售/管理费用趋势与营业规模关系 | 缺列不能将其他费用倒挤成研发；现金余量公式明确只作简化观察 |
| 审计与披露 | 可得审计意见、实际披露日期及原文提示 | 需要 Tushare 权限或用户原文，无数据时显示未核验 |

每项显示至少两个可比期间、计算口径、源值入口、变化与待核实解释；期间不足也显示单期事实。默认最近四期年报，用户可选择季度；累计转单季只在来源语义明确且前期存在时进行，并标出推导公式。财务大幅变化优先提示“可能解释与应找证据”，没有公告不能写成确定原因。

银行、保险、券商等行业与普通工商企业分开适用；身份/行业不能可靠确认时让用户确认，保存用户标注。首版对金融企业隐藏存货周转等不适用指标并解释原因，只展示可靠可比的已提供财务事实；不临时拼一套未经数据支持的金融行业评分。指标“不适用”与“尚无数据”分开。

### 2.2 用户指定的同行比较

新增 `backend/app/analysis/company_comparison.py`、`research/comparison.py`。用户主动选择 2–5 家公司作为默认比较组，最多 10 家；超出时拆成明确新任务，不自动扩展全行业。可从已选板块当前成分提候选，但由用户确认可比性，不将“同概念”直接当“同主营业务”。

比较表展示标的/行业、报告期、披露日期、收入规模、盈利/现金质量、负债结构与当前估值。统一选共同可比期间，无法对齐者显示空缺及原因；不同会计口径不强行拉齐。完整矩阵旁展示有效样本 n/所选 N、覆盖窗口和缺项；任何排序只称“本比较组”，不叫行业排名。

当前 PE/PB 等按来源定义展示；亏损 PE 标“不适用/缺失”而非便宜，负净资产时 PB 不能用普通解释。历史分位仅来自 04 有权取得且覆盖明确的历史估值序列，注明实际窗口/样本，不从同花顺当前快照生成历史。绝对估值、目标价、盈利预测、DCF 不进入首版，避免在缺预测数据时制造精确价格。

LLM 输出围绕“各自强弱项、差异由哪些证据支持、哪些口径影响可比性、还需要什么材料”。不能把最高增速或最低 PE 自动转成最值得买；搜索和用户材料只帮助解释，不直接覆盖结构化比较表。

### 2.3 投资理由与反证跟踪

新增 `backend/app/research/theses.py`、`watchlist.py`；SQLite 新增 watchlist_entries、theses、thesis_observations。关注列表保存研究标的和标签，不保存真实持仓、资金或账户。

每条理由包含用户原文、关联标的、成立所需证据、反证条件、观察指标/期间、创建来源、确认时间。LLM 可以提出候选理由和反证，但用户点击接受后才纳入跟踪；不能自动把模型观点写成用户自己的投资判断。

```text
示例（演示假设，不是任何真实公司的事实）
理由：收入增长正在转为更好的经营现金流。
观察：最近两个可比年度的营收、经营现金流和合并净利润。
反证：现金回款持续弱于利润，且应收增长缺少业务说明。
状态：支持增加 | 支持减弱 | 证据冲突 | 无法判断
```

状态必须有新旧 evidence/metric_refs 及口径一致性，数据不够显示无法判断。用户点击“更新证据并复核”才触发取数与分析；不在后台自动监控、不发送通知、不自动调整投资行为。阈值或观察条件由用户明确设定，UI 同时展示其局限，不包装成交易信号。

用户可以选择只用本地已存资料复核、补充公告后复核、改假设后重分析。每次观察引用具体报告版本；区分新披露、旧数据修订、用户改假设和模型表述改变。理由过期/用户撤销不删除旧报告，只停止默认纳入后续复核。

### 2.4 页面、接口与图表

新增 `backend/app/api/company.py`、`api/watchlist.py`；新增 `frontend/src/api/company.ts`、`api/watchlist.ts`，`pages/Company/index.tsx`、`pages/Compare/index.tsx`、`pages/Watchlist/index.tsx`。Company 展示既有证据与历史报告，点击更新才建任务；Compare 的条件与资料缺口在提交前可检查；Watchlist 展示上次复核时间及待验证事项。

| 本地端点 | 用途 |
| --- | --- |
| GET `/api/companies/{security_id}/research` | 读本地资料和报告索引，不联网 |
| POST `/api/research/tasks` | 复用 03 任务接口，type=company_quality/company_comparison/thesis_review |
| GET/POST `/api/watchlist` | 查询/添加关注标的 |
| PUT/DELETE `/api/watchlist/{id}` | 标签与移除；不级联删除报告 |
| GET/POST `/api/theses` | 读取/创建用户确认的理由 |
| PUT `/api/theses/{id}` | 修改/撤销理由，保留被报告引用的历史内容 |

公司/同行页只读取同一 Report schema，不复制另一种 AI 输出结构。图表采用成熟 ECharts，直接在小型 React 组件封装初始化/dispose/resize，不额外增加第二套图表库或数据状态框架。新增 `frontend/src/components/ResearchChart/index.tsx`，按需注册折线/柱状图；实施时核验官方版本并锁定。

趋势图断点显式显示，禁止连接不存在的财报期；比率、金额、股票价格分轴或分图，不将不同单位混作趋势。图表旁始终有可读表格、单位、日期、出处和缺口；无图表数据时仍能阅读解释。

## 3. 禁止事项与兼容性

不开发量化选股、全市场自动排序、预测收益、目标仓位或交易执行。不能据单一指标定性企业造假/必涨，不将数据少的公司自动判差。任何新增指标都必须有实际字段、公式、适用条件和独立验算；继续复用 03 缺口与 04 用户补充，不开第二套再分析流程。
