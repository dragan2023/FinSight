# 补充数据源调研与选型

## 1. 范围、方法与决定

调研时间：2026-08-31。核对官方接口、SDK/服务文档和可见条款，不使用第三方文章给出的价格或“永久免费”说法。本轮不使用任何个人 Key、不安装数据包；唯一协议探针是对 `https://api.tushare.pro` 提交不含 Token 的空 JSON，返回 HTTP 200 / code 40101，说明 TLS 与认证错误信封可达，不证明业务数据权限。

采用“结构化数据补充”和“解释性证据检索”两条独立路径：同花顺为主结构化源，Tushare 为可选补充；博查和 Tavily 为用户自选搜索服务，Tavily Extract 提供可选正文提取。搜索结果不能直接覆盖财报数值；同花顺不足但用户不配置其他源时，研究仍继续并列出缺口。

## 2. 服务对比与选型

| 服务 | 可补的缺口 | 凭据与计费/权限模式 | 采用决定 |
| --- | --- | --- | --- |
| 同花顺 Financial-API | 当前项目主数据：股票、财务、板块、基金 | 用户 X-api-key；实际能力、频次、存储及模型处理权限按账号确认 | 主源，保留单源完整运行 |
| Tushare Pro | 股票基础、历史 daily_basic 估值、补充三表、主营构成、审计意见、披露计划 | 用户 Token；积分门槛与单独权限并存；个人默认许可不等于商用 | 接入有限只读能力，默认关闭；用户配置并声明适用许可后启用；商业发行/托管不能只靠该声明 |
| 博查 Web Search | 中文公司公告、监管信息、经营解释的网页发现 | 用户 Bearer Key；按官方套餐计费 | 中文检索候选首选，提供搜索适配器；效果优劣须真实样本验证，不宣称已领先 |
| Tavily Search / Extract | 搜索、域名限制、页面正文提取及来源链接 | 用户 Bearer Key；Search 和 Extract 独立消耗 credit | 可选搜索和正文服务；一把 Key 两项能力分别授权 |
| Brave Search API | 网页与时效信息检索 | 用户 subscription token；持久保存结果需要明确 storage rights 套餐 | 首版不接；与证据长期保存的许可需要额外核验 |
| AKShare | 多公开网站行情与财经数据 | 库通常不要求统一 Key，但来源各异；文档强调学术研究及商业风险 | 首版不作为隐式备用源，不将开源代码许可等同数据授权 |
| BaoStock | 历史行情与部分财务指标的备选方向 | 官方站点公开信息不足以在本轮确认所需全部能力与商业授权 | 不进入首版适配器；本计划不依赖它 |
| 巨潮/交易所/公司 IR | 公告和财报原文 | 公开页面访问与商业数据 API 是不同授权 | 作为搜索目标和用户提交原文的优先来源；不调用逆向私有接口，不把商业 API 当免费接口 |

### 2.1 Tushare 的具体价值与限制

优先采用 `stock_basic`、`daily_basic`、`income`、`balancesheet`、`cashflow`、`fina_indicator`；补充 `fina_audit`、`fina_mainbz`、`disclosure_date` 时按 04 的有限任务注册。常规财务接口通常要求 2000 积分，VIP 全市场批量具有其他条件，不能把“Token 有效”理解为所有接口可用，也不承诺固定价格长期不变。[权限与频次](https://tushare.pro/document/1?doc_id=290)、[财务指标](https://tushare.pro/document/2?doc_id=79)、[主营构成](https://tushare.pro/document/2?doc_id=81)、[审计意见](https://tushare.pro/document/2?doc_id=80)、[披露计划](https://tushare.pro/document/2?doc_id=162)

`daily_basic` 为历史每日估值提供基础，但字段单位、交易日、负 PE、上市时长和缺失值必须统一。财务需明确报告类型、合并/母公司、单季/累计、公告日与更新标记，不能拿不同来源的同名字段直接拼接。[每日指标](https://tushare.pro/document/2?doc_id=32)、[利润表](https://tushare.pro/document/2?doc_id=33)、[现金流](https://tushare.pro/document/2?doc_id=44)

官方 HTTP 说明示例使用 HTTP。本项目只实现 HTTPS，前述无凭据探针确认端点可达；任何环境 TLS 失败都不能降级明文或换第三方代理。`fields` 与 `items` 列式信封须检查每行长度和字段重复，Token 不能进入日志。[HTTP 调用](https://tushare.pro/document/1?doc_id=130)

服务条款写明个人、不可转让、非商业用途等许可边界；“用户自带 Key”并不能自动免除应用集成、商业分发、再分发和外部 LLM 处理的授权问题。个人本机可选接入与后续商业上线分别验收；未获适用授权的商业发行须禁用/不包含该适配能力，不因此阻塞同花顺与用户资料路径。[数据服务协议](https://tushare.pro/document/1?doc_id=405)

### 2.2 搜索 API 的具体选择

博查：官方项目给出 `POST https://api.bocha.cn/v1/web-search`，Bearer 认证，query、freshness、summary、count；返回网页链接与逐页内容，不把生成答案当财报数据库。首版使用已确认的这些参数，域名限制若尚未核验，可在结果返回后过滤，不猜参数。官方适配项目可作为薄 REST 客户端参考，不复制其环境凭据策略。[官方适配器](https://github.com/bocha-ai/dsh-web-search-bocha/blob/main/README.zh.md)、[官方 MCP 项目](https://github.com/BochaAI/bocha-search-mcp)、[服务入口](https://bocha.cn/)

Tavily：`POST https://api.tavily.com/search`，显式设 include_answer=false、auto_parameters=false，控制 max_results、topic、search_depth 和域名；正文用 `/extract`，按 URL 返回成功/失败项。用户自行选择 basic/advanced，不能由模型暗中升级费用。Search basic 为 1 credit，advanced 为 2；提取按成功页面和深度计费，页面显示官方计费链接而不硬编码人民币换算。[Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)、[Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)、[credits](https://docs.tavily.com/documentation/api-credits)

Tavily 当前条款涉及用户输入处理与第三方内容责任；不要默认发送私人笔记、完整研究报告或附件到搜索服务。普通检索只传代码、公司名、公开报告期和所需事实；私有材料外发独立告知。抓到页面不等于获得转载全文权，长期保存需满足用户服务条款和内容来源要求。[Tavily 条款](https://www.tavily.com/terms)

Brave 官方明确持久存储需相应权限，并不授予第三方网页内容权利；首版已有两项搜索选择，不再增加配置复杂度。[Brave API 说明](https://brave.com/search/api/)、[服务条款](https://api-dashboard.search.brave.com/documentation/resources/terms-of-service)

### 2.3 不选免费聚合库作自动兜底

AKShare 官网将用途定位为学术研究并提示商业风险；在本项目中用抓站库绕过主源限流，会带来来源、字段变化、网络与许可的不确定性，因此首版不采用。不是否定其研究用途，也不是认为“无 Key”的数据天然不可信。[AKShare 概览](https://akshare.akfamily.xyz/introduction.html)

BaoStock 本轮访问和公开资料不足以完成目标字段、更新时间及商用许可核验，决策为排除首版，而不是留下隐式备用开关。[官网](https://www.baostock.com)

巨潮是公开披露的重要原文来源，但网站内部请求和开放商业 API 不等价；通过搜索发现原文、用户上传已有文件或受限读取公开 URL 补充，不复制登录态、不逆向签名、不绕过反爬。[巨潮官网](https://www.cninfo.com.cn/)

## 3. 来源选择、授权和冲突规则

### 3.1 路由

1. 用户明确指定来源时遵从指定来源，无权限则保留缺口，不暗换来源。
2. 用户开启“允许已配置备用源”时，结构化同花顺失败/缺字段可向已授权 Tushare 请求同一标的和可比报告期；记录回退原因。
3. 原因、公告和业务构成问题可用选定搜索服务，先发现来源，再取授权原文。没有全文时将结果标记为线索。
4. 用户上传材料和手工输入优先保留其声明口径；发现与官方数据冲突时并列展示，用户可选择采用哪一版重分析，原证据不覆盖。

### 3.2 存储与外发

每个证据含 storage_policy=`full|excerpt|reference_only|ephemeral`、许可备注及来源。全文权利未明确时不默认永久归档搜索/提取正文；reference_only 报告需明确“未保存原文，不能完整离线复核”。对禁止持久保存的结果，不能通过换名“证据摘要”绕过限制。允许长期保存的用户资料/授权数据才使用完整不可变证据路径。

所有已接入能力必须在统一配置页出现，含无 Key 的本地解析/公开读取及共享 Key 的 Tavily Extract。任务只引用 profile_id 和配置版本，不把凭据复制进任务或证据。不要提供应用开发者垫付模式或后台公共 Key。

## 4. 采用前的实际验收

静态文档支持只能证明可设计，不能证明账号已开通。04 须用用户的 Key 执行有限探针：同一公司同一期三表、历史每日指标窄窗口、公开公告检索和一页正文，验证字段映射、来源时间和错误分类。比较搜索效果采用一组可核对原文的公开问题，记录原文命中、时间正确性、失败、延迟和实际计费；未实测时不发布“中文最佳”等断言。

以上授权说明是工程发布约束，不代替针对商业发行的法律意见；08 要求取得适用合同/许可依据后才开放相应商业能力。
