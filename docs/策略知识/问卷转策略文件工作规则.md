# 问卷转策略文件工作规则

## 1. 目标

把业内人士的自然语言经验转成可检索、可确认、最终可实现的策略资料，同时保留“不确定”和“依赖经验”的真实边界。转换不是替作者创造策略，也不是替策略背书。

## 2. 输入与输出

输入：原始问卷、访谈补充、案例和附件。

输出：

1. 原始问卷存档：保持原文，不覆盖、不润色。
2. 歧义与缺口清单：逐条列出需要确认的问题。
3. 策略方法卡草稿：使用 `业内策略方法卡模板.md`。
4. 验证报告或验证计划：使用 `业内策略验证报告模板.md`；没有真实证据时只写验证计划。
5. 原作者确认表：记录原话、规范化规则和确认结果。

## 3. 转换顺序

### 3.1 保存原始表达

1. 为问卷生成唯一编号和收到日期。
2. 原文只读保存；错别字也不直接覆盖，可在整理稿中解释。
3. 附件记录来源、日期和使用授权。
4. 原始问卷默认不标记为知识库中的“已审核策略”。

### 3.2 提取策略骨架

先只提取以下内容，不补细节：

| 骨架字段 | 主要问卷来源 |
|---|---|
| 投资对象与排除对象 | 3.1 |
| 目标持有期与检查频率 | 3.2–3.3 |
| 适用与禁用环境 | 3.4、8.4 |
| 关注、买入和否决条件 | 4.1–4.3 |
| 行动时点与冲突优先级 | 4.4–4.5 |
| 持有、加仓和退出 | 5.1–5.5 |
| 仓位与风险 | 6.1–6.5 |
| 数据、来源和可得时间 | 7.1–7.4 |
| 正例、反例与边界例 | 8.1–8.3 |
| 失效与版本变化 | 8.4–8.5 |

### 3.3 给每条内容标记确定性

| 标记 | 含义 | 处理方式 |
|---|---|---|
| 已明确 | 原话足以形成唯一规则 | 写入方法卡，并保留问卷引用 |
| 可建议 | 含义清楚但缺阈值或时间 | 提出 1–3 个候选表达，等待确认 |
| 经验裁量 | 作者明确依靠经验 | 原样保留为人工判断，不擅自量化 |
| 矛盾 | 不同回答不能同时成立 | 列入澄清问题，不选择其中一个 |
| 缺失 | 问卷没有提供 | 写“未说明”，不得使用行业惯例代填 |

## 4. 不允许 AI 擅自完成的内容

1. 买入、退出和止损阈值。
2. 信号使用当日收盘还是下一交易日数据。
3. 仓位上限、行业上限和最大回撤。
4. 多个信号冲突时的优先级。
5. 成本、滑点和无法成交的处理。
6. 适用市场状态和停用条件。
7. 把“大概率、通常有效、比较稳”等表述转换成具体胜率。
8. 把成功案例转换成一般有效性结论。

## 5. 澄清方式

避免向作者重新发送技术模板。每个缺口改写成二选一或具体案例问题，例如：

| 不推荐问法 | 推荐问法 |
|---|---|
| 请定义信号执行时点 | 如果收盘后才看到信号，你通常第二天开盘买，还是等盘中再次确认？ |
| 请定义止损参数 | 亏损到什么程度时你一定会重新检查？有没有无论如何都会卖出的程度？ |
| 请定义冲突优先级 | 基本面仍看好但价格跌破你关注的位置时，你通常继续持有还是先退出？ |
| 请提供市场状态分类 | 哪种盘面下你会主动少做或不做？你当时看什么现象判断？ |

一次澄清只问影响最大的 5–8 个问题，避免把访谈重新变成考试。

## 6. 关键阻断项

以下任何一项仍无法确认时，可以建立“策略假设卡”，但不能建立可执行策略或标记 `approved`：

1. 适用投资对象。
2. 目标期限或退出逻辑。
3. 最基本的入场条件。
4. 信号与行动的时间顺序。
5. 明确的禁止交易或风险退出条件。
6. 所用数据在当时是否真实可得。

仓位、成本或组合规则不完整时，可以进行信号研究，但不得把结果解释为可执行投资方案。

## 7. 原作者确认表

| 编号 | 问卷原话/位置 | 规范化规则 | 整理者是否补充 | 作者确认 | 修改意见 |
|---|---|---|---|---|---|
| R-01 | | | 否/候选表达 | 是/否/待定 | |

确认要求：

1. 作者至少确认投资对象、买入、退出、时点、仓位风险、禁用条件和失效条件。
2. “经验裁量”允许保留，但必须说明它不能被程序自动执行。
3. 作者否认或无法确认的规则从正式方法卡删除，不能只改措辞掩盖分歧。
4. 确认后的文档生成新版本和生效日期。

## 8. 验证报告处理

1. 作者提供回测时，先记录原始口径和局限，不能直接复制收益结论。
2. 只有案例没有统计时，案例进入证据索引，验证结论写“样本不足”。
3. 没有任何历史数据时，生成“验证计划”，不生成虚假的验证结果。
4. 外部验证与 FinSight 本机实验分开列示。
5. 本机实验和前向影子验证未通过前，方法卡只能是实验性或候选资料。

## 9. RAG 入库顺序

1. 原始问卷：原则上本地存档；确需入库时标记 `source + unreviewed`。
2. 未确认的方法卡草稿：`hypothesis + unreviewed`。
3. 作者确认且内部复核完成的方法卡：`strategy + approved`。
4. 被新版本替代的方法卡：改为 `retired`，不删除历史版本。
5. 验证报告应明确它支持的是哪一方法卡版本，不能跨版本引用。

## 10. 质量验收

- [ ] 原始问卷和规范化文档可以逐条回链。
- [ ] 所有新增数字和阈值均有作者确认来源。
- [ ] 不确定、经验裁量、矛盾和缺失没有被隐藏。
- [ ] 方法卡中的入场、退出和时点不存在相互冲突。
- [ ] 验证报告没有把案例或外部声明冒充本机验证。
- [ ] 作者已经确认关键规则。
- [ ] 只有满足内部规范的版本才标记为 `strategy + approved`。
