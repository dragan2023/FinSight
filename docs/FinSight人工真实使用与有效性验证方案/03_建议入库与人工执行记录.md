# 03 — 建议入库与人工执行记录

## 1. 摘要

- 优先级：高
- 预计工作量：每日 10—20 分钟
- 直接依赖：02 已生成最终建议
- 阶段目标：确保顾问结论、预测封存、研究报告和真实券商成交能够一一对应。

## 3. 任务详情

### 3.1 检查自动入库

1. 顾问回答完成后打开“执行建议台账”。
2. 核对证券代码、基准日期、方向、建议档位、持有期和建议正文。
3. 打开“研究预测封存”，确认非拒答建议是否生成 H5 预测。
4. 记录建议 ID，后续券商成交和复盘都使用该 ID 对应。

### 3.2 必要时手工封存预测

仅当建议已经生成但自动预测封存缺失时，才手工填写完整代码、名称、基准日、H5、上涨/震荡/下跌概率、收益阈值、核心依据、最强反证和失效条件。三项概率合计必须为 100%，且最高概率必须唯一。

手工封存是补全记录，不得修改顾问原始方向和概率来美化结果。

### 3.3 保存研究报告

需要进一步核验的股票进入“研究工作台”，选择证券、填写具体问题并点击“开始研究”。完成的报告应能在“研究资产库”中查到，并与同一天的建议相互引用。

### 3.4 记录真实成交

FinSight 当前没有券商下单和完整持仓盈亏账本。实际执行买入时，必须在券商导出的成交记录或独立只读台账中保存：

1. FinSight 建议 ID；
2. 完整证券代码；
3. 委托与成交时间；
4. 成交价格、数量、佣金、印花税和其他费用；
5. 平仓时间、价格与原因；
6. 未执行时的原因。

真实盈利只按券商成交净额计算，不能用预测命中代替。

## 4. 修改与数据范围

- 顾问记录：`data/db/finsight.db` 的 `advisor_sessions`、`advisor_messages`、`advisor_runs`
- 建议台账：`advice_ledger`
- 预测封存：`research_predictions`
- 研究报告：`research_reports`
- 实际成交：券商成交单或用户独立只读台账；当前项目没有对应交易表

## 5. 禁止事项

1. 不直接操作 SQLite 修补或删除不利结果。
2. 不在建议生成后补写早于生成时间的“历史预测”。
3. 不把未成交委托计作真实交易。
4. 不忽略佣金、税费、滑点和无法成交的情况。
5. 不把多个建议合并为一笔无法追溯的成交。

## 6. 验收标准

- [ ] 每个顾问最终建议都能在建议台账中找到。
- [ ] 每个可执行建议都有对应的 H5 预测封存。
- [ ] 原始建议与封存内容一致。
- [ ] 每笔实际成交能追溯到唯一建议 ID。
- [ ] 未执行建议也记录原因。
- [ ] 券商记录包含全部交易费用。
