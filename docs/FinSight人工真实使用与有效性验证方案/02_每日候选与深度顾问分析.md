# 02 — 每日候选与深度顾问分析

## 1. 摘要

- 优先级：最高
- 预计工作量：每日 30—60 分钟
- 直接依赖：01 已完成且数据真实可用
- 阶段目标：每天用同一套规则选出最多 3 个候选，并让顾问真实调用模型、行情、F10、RSS、知识库和搜索生成可审计建议。

## 2. 前置阅读

1. `frontend/src/pages/MarketReviewPage.tsx`
2. `frontend/src/pages/MarketExplorerPage.tsx`
3. `frontend/src/pages/AdvisorPage.tsx`
4. `backend/app/advisor/graph.py`
5. `backend/app/advisor/output_models.py`

## 3. 任务详情

### 3.1 固定候选生成规则

1. 从“盘后复盘”取热度前 5。
2. 从“全市场”取成交额前 10。
3. 合并、去重后排除 ST、停牌、次日无法正常买入的连续涨停股，以及身份无法确认的证券。
4. 同时出现在两张榜单的股票优先，其余按成交额排序。
5. 每天最多保留 3 只；合格标的不足 2 只时不凑数。
6. 在“研究总览”确认证券名称、完整代码和最新交易日。

### 3.2 逐只发起顾问研究

1. 进入“AI 顾问”。
2. 每只股票点击一次“新建会话”。
3. 选择 `deep` 模式。
4. 勾选“本次允许联网搜索”。
5. 把下面提示词中的日期、名称和完整代码替换后原样提交：

```text
今天是 YYYY-MM-DD，A 股已经收盘。请对【股票名称，完整代码】做一次未来 5 个交易日的建仓决策研究。

我的目标：判断下一个交易日是否值得建立试探仓；只评估这一只股票，不扩大到其他标的。

资金约束：这只股票最多占总资金 10%；单笔可接受最大亏损 2%；不融资、不追涨停、不在证据不足时买入。

请实际使用本轮能够取得的同花顺最新完整日 K、历史日 K、F10 财务与估值、资金/异动数据、本地 RSS、私有知识库以及联网搜索摘要。搜索和 RSS 只能作为线索，关键事实必须交叉验证。

必须给出：明确方向、5 个交易日上涨/震荡/下跌概率、建议档位、关键证据、最强反方证据、什么情况下判断作废、可量化跟踪哨，以及是否满足“明日可试探买入”。如果候选策略或证据门禁不满足，请明确等待或拒答，不要为了迎合我而改成买入。
```

### 3.3 判断输出是否真实可用

页面必须显示模型调用过程、证据来源和最终建议。只有同时满足以下条件，才把结果视为候选买入信号：

1. 方向为加仓或买入，而非等待、减仓或拒答。
2. 建议档位至少为 `trial_buy_signal`。
3. 没有未解决的关键证据冲突。
4. 给出了明确失效条件、风险限制和可跟踪观察哨。

任何一项不满足，当天都不买。禁止通过连续追问把等待结论诱导成买入。

## 4. 修改与数据范围

顾问会话、消息、运行轨迹和最终建议写入 `data/db/finsight.db` 中的 `advisor_sessions`、`advisor_messages`、`advisor_runs` 与 `advice_ledger`。符合条件的研究预测还会写入 `research_predictions`。

## 5. 禁止事项

1. 不使用盘中波动临时替换固定候选规则。
2. 不删除等待、拒答或亏损建议。
3. 不对同一标的重复生成，直到出现想要的答案。
4. 不把候选列表本身当作系统已经给出的买入建议。
5. 不绕过候选策略与证据门禁。

## 6. 验收标准

- [ ] 每日候选可由固定榜单规则复现。
- [ ] 每只候选使用独立 Deep 会话。
- [ ] 联网搜索已勾选且页面显示真实调用结果。
- [ ] 行情、F10、RSS、知识库和搜索的成功或失败均可见。
- [ ] 最终建议包含方向、概率、档位、证据、反证、失效条件和观察哨。
- [ ] 连续 10 个交易日无 `trial_buy_signal` 时，明确记录为“当前版本实际荐股不可用”。
