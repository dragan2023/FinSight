# 官方模型接入说明

## 1. 预设与核验范围

核验日期：2026-08-31。默认使用用户指定的最新模型；模型可用性仍受账户权限、余额和地域影响。目录不是用户账户的实时模型列表，不会后台自动调用计费接口、自动升级已有配置或失败后切换模型。

| 官方客户端 | 默认 API 模型 ID | 本项目配置能力 |
| --- | --- | --- |
| DeepSeek | `deepseek-v4-flash-vision-exp` | 思考开关、low/high/max、图像许可与精度 |
| GLM（智谱通用 API） | `glm-5.3-flash` | 强制思考、low/high/max、图像与视频许可 |
| Qwen（百炼） | `qwen3.8-flash` | 思考开关、思考预算、图像与视频许可、视频 FPS、地域和业务空间 |

可选同代模型包括 DeepSeek V4 Flash / Pro、GLM-5.3、Qwen3.8 Max。Qwen3.5 Omni Plus 作为当前全模态系列提供音频输入，不能开启思考。未接入 Coding Plan 专用端点；不将套餐凭据自动发送到通用 API 以外的地址。

复用现有 `openai.AsyncOpenAI` 和共享 `httpx.AsyncClient`，通过三家官方支持的兼容接口直连，没有引入中转服务或第二套 SDK。客户端工厂读取活动配置，前端只保存服务商与能力选项；模型 Key 始终由后端解密后加入 Authorization。

## 2. 使用流程

1. 打开模型设置，选择任意官方客户端，填入该服务商通用 API Key，保存即可。默认名称、地址、最新模型、输出预算与超时已预置；首个配置默认激活。
2. 首次保存请求显式携带 `initialize_encryption: true`，仅在根密钥缺失且没有加密记录时生成 `.env` 根密钥，立即生效。普通启动不生成密钥。根密钥无效或旧记录不可解密时必须恢复原密钥，不能覆盖。
3. 需要切换能力时编辑模型和模式；已保存配置的参数会在重启后保留。Qwen 默认为北京，在高级设置可选择新加坡；两地密钥不通用。业务空间 ID 可留空，或填写后使用官方 maas 专属地址。
4. 在模型试用区输入提示词；支持的多模态通过单个公开 HTTPS 素材 URL 传入。确认外发和计费后才能发送。试用只返回最终文本，不保存对话、素材 URL、推理过程或模型原始响应。
5. 连接测试可分别验证聊天或工具协议。工具测试只校验无副作用的 `connection_probe`，不执行工具。GLM 不调用未经核验的 `/models`；选择模型列表测试会提示改用聊天且不发起外部请求。

手动确认的单次请求不要求修改环境开关；未确认的调用仍须 `FINSIGHT_RUN_LIVE_LLM_TESTS=true`。该变量只供显式启用的无人值守验证，默认 false。所有测试使用无效夹具密钥和 MockTransport，开发过程中未发起真实模型请求。

## 3. 官方参数映射

### 3.1 DeepSeek

地址为 `https://api.deepseek.com`，模型 ID 使用 `deepseek-v4-flash-vision-exp`。它支持图像和可切换思考，实验版本可能变化。非思考时发送配置的 Temperature；思考时发送 `thinking.type=enabled` 并省略 Temperature。推理强度为 `reasoning_effort`，省略使用官方默认 high。

图像作为用户消息的 `image_url` 内容块；`image_url.detail` 可选 auto/low/high/original，low 降采样，其余保留原始尺寸。工具选择使用 auto；不使用要求 beta 端点的 strict 模式。未来实现连续工具回合时，必须按官方要求回传对应推理字段；本次单轮试用和协议探针不实现 Agent 工具循环。

依据：[模型与能力](https://api-docs.deepseek.com/quick_start/pricing/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[视觉输入](https://api-docs.deepseek.com/guides/vision/)、[Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion/)。

### 3.2 GLM

地址为 `https://open.bigmodel.cn/api/paas/v4`。GLM-5.3 Flash 是原生视觉模型，GLM-5.3 为文本模型。两者 `thinking.type` 仅支持 enabled；前端锁定思考开关，后端拒绝 disabled。推理强度支持 low/high/max，默认遵从官方 max。发送 `thinking.clear_thinking=false`；当前单轮请求不持久化推理内容。

图像内容块为 `image_url.url`，视频为 `video_url.url`。Temperature 限制在 0–1。官方通用接口 `tool_choice` 仅支持 auto，不发送 OpenAI 强制函数对象或 strict；没有返回工具调用时只报告“未完成工具验证”，不将普通回复当作通过。

依据：[GLM-5.3 Flash](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[GLM-5.3](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)、[Chat Completion 参数](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)、[多模态视频格式](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.6v)、[官方 OpenAI 兼容接入](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)。

### 3.3 Qwen

北京默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`，新加坡默认 `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`。填写业务空间后改为 `https://{WorkspaceId}.{region}.maas.aliyuncs.com/compatible-mode/v1`，region 分别为 cn-beijing / ap-southeast-1；官方仍支持原 DashScope 地址。

Qwen3.8 Flash / Max 使用 `enable_thinking` 和可选 `thinking_budget`。页面预置预算 4096，可留空采用官方默认；完整输出使用推荐的 `max_completion_tokens`，避免旧 `max_tokens` 对思考与最终回复范围的歧义。视频 FPS 放在 `video_url` 内容块同层，允许 0.1–10，留空使用官方默认。

Omni 不发送思考参数，强制 stream=true、modalities=[text]。后端合并流式文本和工具参数片段后返回前端，不显示或缓存推理字段。音频通过 `input_audio.data` URL 和 wav/mp3 格式传入；不提供语音生成或实时通话功能。

依据：[Qwen3.8 Flash](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)、[思考模式与预算](https://help.aliyun.com/zh/model-studio/deep-thinking)、[视觉与 FPS](https://help.aliyun.com/zh/model-studio/vision)、[Qwen Omni](https://help.aliyun.com/zh/model-studio/qwen-omni)、[地域与地址](https://help.aliyun.com/zh/model-studio/regions)。

## 4. 实现与边界

- 服务端唯一能力目录：`backend/app/model_config/providers.py`；前端通过 `/api/models/providers` 读取。模型 ID、官方地址、模式和输入许可均在保存时校验，不接受任意厂商参数透传。
- SQLite schema v2 增加 provider 和 options_json；v1 原配置按 custom 迁移，保留原密文、地址、参数与活动状态，不进行破坏性重建。
- 同时最多一个试用或测试请求；不自动重试、跟随重定向或使用环境代理；超时可能仍被上游计费。输出预算是本项目 64–32768 的验证上限，不是模型上下文上限。
- 只接受单个公开 HTTPS 素材 URL，不在本机抓取或预览，不支持文件上传、PDF 文件解析、多素材组合、语音生成和 WebSocket 实时会话。输入许可不是服务商额外功能开关，只影响本机发送哪些内容块。
- 内容只作为文本渲染，不能执行模型返回的 HTML、脚本或工具。流中断、空回复、输出截断和错误会明确呈现；原始错误、密钥、推理字段不返回前端。
- 三家账户的有效权限、配额与真实多模态效果仍须用户保存自己的 Key 后手动验证。本机开发验证不能替代服务商实际联调。

## 5. 验证

执行项目根 `scripts/test_backend.ps1`，以及 frontend 中的 `npm run build`、`npm run lint`、`npm run test`。后端覆盖新旧存储迁移、只填密钥、显式初始化与根密钥丢失、地域变更、模式非法组合、实际 HTTP JSON、流式完整性、多模态内容结构和外发门禁；前端覆盖预设保存、必填项、GLM 模式锁定、Omni 联动与试用同意。

本次验证结果：50 项后端测试、12 项前端测试通过，build/lint 与 pip check 通过。浏览器验证默认预设、GLM 思考锁定、Qwen Omni 联动与地域地址、390px 窄屏无横向溢出。实际项目配置库保持空库，没有导入真实 Key 或发起外部计费请求。
